# Ticket #50 — AI Advisor Notifications Enhancement

## What was implemented

### Backend (apps/api/)

1. **New service methods** in `ai.service.ts`:
   - `analyzeMissingSections(content, stage?)` — analyzes document content for missing sections, returns prioritized list
   - `notificationReply(notificationId, message, documentContent)` — processes user replies to AI advisor notifications, returns AI follow-up with suggested actions

2. **New endpoints** in `routes/ai.ts`:
   - `POST /api/ai/seed-from-stage` — accepts `{ documentId, fromStage, toStage, content }`, delegates to existing `seedNextStage()` service method
   - `POST /api/ai/missing-sections` — accepts `{ content, stage? }`, returns missing section analysis
   - `POST /api/ai/notification-reply` — accepts `{ notificationId, message, documentId, content? }`, returns AI reply with suggested actions

### Frontend (apps/web/)

1. **API client functions** added to `lib/api.ts`:
   - `seedFromStage()`, `analyzeMissingSections()`, `replyToNotification()`

2. **AIAdvisor component** enhancements:
   - **Pre-fill offer notification (Tier 2)**: When a document has a stage, offers to seed the next lifecycle stage. Accept triggers `seedFromStage` and applies generated content.
   - **Missing sections alert (Tier 2)**: After quality analysis completes, runs missing sections analysis and shows notification with option to auto-add missing sections.
   - **Reply functionality**: Wired the reply input to `POST /api/ai/notification-reply`. AI replies appear as new Tier 2 notifications. Reply is enabled on Tier 2 notifications (prefill_offer, missing_sections, ai_reply).

### Tests

- 7 new route tests for the 3 new endpoints (including validation/400 cases)
- 5 new service tests for `analyzeMissingSections` and `notificationReply` (including fallback/parse-failure cases, stage context verification)
- All 318 API tests pass, all 23 web tests pass, TypeScript clean on both packages
