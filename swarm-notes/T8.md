# T8: E2E Tests for Notifications

## What was implemented

Created `e2e/notifications.spec.ts` with 5 tests covering the notification system:

1. **T8.1: Bell shows unread count** — Mocks `GET /api/notifications/unread-count` returning `{ count: 3 }`, asserts the badge displays "3".
2. **T8.2: Click bell opens panel** — Clicks the notification bell, asserts `notification-panel` becomes visible.
3. **T8.3: Panel shows notification items** — Mocks `GET /api/notifications` returning 2 items, asserts 2 `notification-item` elements render.
4. **T8.4: Mark all as read clears badge** — Uses mutable `markedAllRead` flag so that after `PATCH /api/notifications/read-all`, the unread-count mock returns 0. Asserts the badge disappears.
5. **T8.5: Filter tabs work** — Mocks 3 notifications (2 unread, 1 read). The `GET /api/notifications` mock inspects the `read` query param to filter results. Asserts count changes when toggling between "All" and "Unread" filters.

## Patterns used

- Imports `test`, `expect`, `SEED` from `./fixtures/test-base` and `SEL` from `./fixtures/selectors`.
- Uses `page.route()` for all API mocking (same pattern as `invite-accept.spec.ts`).
- Uses `authenticatedPage` fixture which handles auth mocks and navigates to `/dashboard`.
- Each test re-navigates with `page.goto('/dashboard')` after setting up route mocks so the UI fetches the mocked data.
