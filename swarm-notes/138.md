# Ticket #138 — Agent Permission Controls

## What was built

### Backend: Permission check endpoints (`apps/api/src/routes/permissions.ts`)
- `GET /api/permissions/check?teamId=X&action=Y&resourceType=Z&resourceId=W` — checks if authenticated user can perform action Y. Returns `{ allowed, role, requiredRole, reason? }`.
- `GET /api/permissions/roles?teamId=X` — returns user's role, full hierarchy, allowed actions, and the action-to-role mapping.

Action-to-role mapping:
- `read` -> viewer
- `edit`, `create` -> editor
- `deploy`, `merge` -> developer
- `delete`, `manage` -> admin
- `transfer` -> owner

Reuses the same role hierarchy from `apps/api/src/middleware/permissions.ts` and duplicates `getUserTeamRole` locally to keep the route self-contained (the middleware version is not exported).

Registered in `apps/api/src/app.ts` at prefix `/api/permissions`.

### Backend tests (`apps/api/src/__tests__/routes/permissions.test.ts`)
- 8 tests covering: allowed/denied checks, non-member handling, missing params, unknown actions, specific action-role mappings (deploy->developer, transfer->owner), roles endpoint with hierarchy + allowed actions, and 403/400 error cases.

### CLI: `packages/cli/` (new package in worktree)
Since the CLI package didn't exist in this branch, scaffolded the minimal package with `client.ts`, `utils/output.ts`, and `index.ts` following main-branch patterns.

### CLI command (`packages/cli/src/commands/permissions.ts`)
- `nyx permissions check --team-id <id> --action <action> [--resource-type <type>] [--resource-id <id>] [--format json|table]` — exits with code 1 if not allowed.
- `nyx permissions roles --team-id <id> [--format json|table]` — shows current role and what actions are available.

### CLI tests (`packages/cli/src/__tests__/permissions.test.ts`)
- 3 tests: registration verification, check subcommand options, roles subcommand options.
