# Ticket #287 — Vector similarity search service (retrieveChunks)

## What was done

1. **Retrieval service** (`apps/api/src/services/retrieval.service.ts`)
   - `retrieveChunks(query, teamId, options?)` generates an embedding for the query via `embeddingService.generateEmbeddings`, then runs a pgvector cosine similarity query against `doc_chunks`.
   - Filters by `org_id = teamId`, applies a similarity threshold (default 0.3), orders by similarity descending, and limits to `topK` (default 5).
   - Returns `{ content, docId, score, chunkIndex }[]`.

2. **API route** (`apps/api/src/routes/retrieval.ts`)
   - `POST /api/retrieve` accepts `{ query, teamId, topK? }` and returns matching chunks with scores.
   - Registered in `app.ts` at prefix `/api/retrieve`.

## Notes
- Uses raw SQL via Drizzle's `sql` template for the `<=>` cosine distance operator since Drizzle has no built-in pgvector support.
- The HNSW index on `doc_chunks.embedding` (with `vector_cosine_ops`) is already defined in the schema, so queries benefit from approximate nearest neighbor search.
- All tsc errors are pre-existing module resolution issues unrelated to this change.
