# swarm-notes/344.md — Switching files shows stale doc

## Summary
Two compounding bugs in `apps/web/src/pages/DocumentEditor.tsx` caused
clicking a different file in the Explorer to (a) flicker the previous
document's content under the new document's URL, and (b) persist the
previous document's content into the new document's database row via
a stale debounced save firing after navigation.

## Root cause
1. **Debounced save crossed `id` boundaries.** `scheduleSave` armed a
   500ms `setTimeout` that called `saveMutation.mutate(updates)`. The
   `mutationFn` was `(data) => updateDocument(id!, data)`, where `id`
   came from the latest closure. Nothing cancelled the pending timer
   on `id` change — the existing `[id]` cleanup effect only reset
   `initialised.current`. So if the user navigated A → B inside the
   debounce window, the timer fired with A's `updates` and B's `id`.

2. **`initialised` ref-flag seeding had an effect-ordering gap.** The
   `[id]` reset and the `[doc]` seed were in two separate effects, both
   running after render. On the first render after `id` changed,
   `initialised.current` was still `true` from the previous doc, so the
   `[doc]` effect did not re-seed and the editor rendered the previous
   doc's `title`/`content` under the new URL.

## Fix
Edited only `apps/web/src/pages/DocumentEditor.tsx`.

### Bug 1 — debounced save
- Added a `latestIdRef` that is updated synchronously on every render
  to mirror the current route `id`.
- Added a `useEffect` keyed on `[id]` that returns a cleanup which
  clears `debounceTimer.current` on `id` change or unmount (the
  "belt").
- In `scheduleSave`, captured `const capturedId = id` at timer-arm
  time. Inside the timer callback, bail out if
  `latestIdRef.current !== capturedId` (the "suspenders"). The
  mutation is therefore never invoked with a stale `updates` payload
  after navigation — even if the cleanup hasn't yet fired due to a
  race.
- Re-added `saveMutation` to the `scheduleSave` dependency array (the
  TODO that the issue called out).
- Hardened `saveMutation.onSuccess` to write into
  `queryClient.setQueryData(['document', updated.id], updated)` (the
  server-returned id) instead of the closed-over `id`, so even if a
  legitimate doc-A save resolves after the user has navigated to doc
  B, A's response lands in A's cache slot.
- Hardened `onMutate` / `onSuccess` / `onError` to only flip
  `saveState` when `latestIdRef.current` still matches the doc the
  mutation is for.

### Bug 2 — local state flashing previous doc
- Removed `initialised` ref entirely.
- Added a `seededIdRef` that tracks the id whose values are currently
  in local state. During render, if `seededIdRef.current !== id`, we
  synchronously call `setTitle('')`, `setContent('')`,
  `setSaveState('saved')`, and clear any pending debounce timer. This
  is the "synchronous setState during render" pattern documented by
  the React team — it triggers an immediate re-render with empty
  state instead of leaving a frame where the previous doc's content
  is visible under the new URL.
- Replaced the two seeding effects with a single `useEffect` keyed on
  `[id, doc]` that seeds title/content **only when**
  `doc.id === id` and local state is empty. The "is empty" guard
  prevents subsequent refetches from clobbering user edits.
- The existing `if (isLoading) return <Loading />` early-return
  already covers the in-between render — combined with the
  synchronous clear, the editor shows the loading placeholder during
  the transition rather than stale content.

## Tests added
1. **`apps/web/src/__tests__/pages/DocumentEditor.test.tsx`** — three
   Vitest + React Testing Library tests:
   - Types into title at `/documents/doc-a`, navigates to
     `/documents/doc-b` inside the debounce window, asserts that
     `updateDocument` is never called with `('doc-b', { title: 'Edited A title' })`.
   - Slows down doc B's fetch and asserts that immediately after
     navigation the editor renders the loading placeholder, never
     simultaneously displaying doc B's URL with doc A's title /
     content.
   - Confirms the seeding behaviour for new docs and that a refetch
     does not clobber the user's in-progress edits.
2. **`e2e/editor-stale-doc.spec.ts`** — Playwright regression test:
   loads doc B (baseline), opens doc A, types a character, switches
   to doc B inside the debounce window, then reloads doc B and
   asserts its title/content match the baseline (i.e. the typed
   character did not leak across).
