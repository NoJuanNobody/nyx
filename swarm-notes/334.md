# 334 — Repos silently stuck "Disconnected" when WEBHOOK_BASE_URL is unset

## What changed

**apps/api**
- `src/app.ts`: `buildApp()` now logs a `warn`-level message ("WEBHOOK_BASE_URL not configured — GitHub webhook registration is disabled; all synced repos will appear Disconnected") immediately after Fastify is instantiated, so operators see the degraded mode at startup instead of only after reading the source.
- `src/routes/integrations.ts`:
  - Added a shared helper `registerRepoWebhook({ accessToken, owner, name, webhookSecret })` near the top of the module that returns a discriminated union `{ status: 'ok', webhookId } | { status: 'skipped', reason: 'webhook_base_url_unset' } | { status: 'error', error }`. Centralises the three paths (bulk save, post-create, reconnect) so the success path stays in one place per the issue's note.
  - `PUT /:id/github/repos`: now routes through `registerRepoWebhook` for every added repo. Response body is extended to `{ ok, webhookRegistrationEnabled, failed: [{ repo, error }], skipped: [fullName] }`. Webhook deletion for removed repos is still gated on `webhookRegistrationEnabled` (nothing to delete server-side when it's off).
  - `POST /:id/github/repos/create`: also routes through the helper. Response now includes `webhookRegistrationEnabled`, `webhookSkipped`, and `webhookError` so the UI can distinguish "not attempted" from "attempted and failed".
  - `GET /:id/github/synced-repos`: response now includes `webhookRegistrationEnabled: boolean` alongside `repos`. This is the endpoint the Repositories page already reads, so no extra round-trip is needed.
  - New endpoint `POST /:id/github/repos/:repoName/reconnect` (admin-gated via `requireRole({ minimumRole: 'admin', source: 'integration' })`) that reuses `registerRepoWebhook` and persists the new webhook id into `cfg.webhookIds`. Returns:
    - `200 { ok, fullName, webhookId, syncStatus: 'active' }` on success
    - `503 { error: 'webhook_registration_disabled', message }` if the server has no `WEBHOOK_BASE_URL`
    - `502 { error: 'webhook_creation_failed', message }` if GitHub rejects the create call
    - `400` if the integration has no access token, `404` if the repo isn't in `selectedRepos`.
- New test file `src/__tests__/routes/integrations-webhook-base-url.test.ts` (5 tests):
  1. `PUT /repos` with env unset does not call `createWebhook`, returns `{ webhookRegistrationEnabled: false, failed: [], skipped: [...] }`, and persists `webhookIds: {}`.
  2. `GET /synced-repos` with env unset exposes `webhookRegistrationEnabled: false` and every repo's `syncStatus` stays `'disconnected'`.
  3. Reconnect with env set calls `createWebhook` with the correct base URL + secret, persists the new id, and returns `syncStatus: 'active'`.
  4. Reconnect with env unset returns `503 { error: 'webhook_registration_disabled' }` and never calls `createWebhook`.
  5. Reconnect when `createWebhook` throws returns `502 { error: 'webhook_creation_failed', message: '…422…' }`.
- The test file supplies a per-file `vi.mock('../../lib/config.js')` that exposes a getter, so individual test cases can flip `WEBHOOK_BASE_URL` without affecting the global setup mock.

**apps/web**
- `src/lib/api.ts`:
  - Extended `saveSelectedRepos` return type to `SaveSelectedReposResponse { ok, webhookRegistrationEnabled, failed, skipped }`.
  - Added `SyncedReposResponse` wrapping `{ repos, webhookRegistrationEnabled }`; `fetchSyncedRepos` now returns it.
  - Added `reconnectRepo(integrationId, repoFullName)` that `POST`s to the new endpoint.
- `src/pages/Repositories.tsx`:
  - `StatusBadge` now takes `webhookRegistrationEnabled`. When the flag is `false`, the amber "Disconnected" badge is replaced with a slate "Sync disabled" badge so users understand the cause is server-side, not per-repo (per the issue's closing note). Active remains unchanged.
  - New `WebhookRegistrationDisabledBanner` component, rendered above the repo table (and in the empty-state path) when `webhookRegistrationEnabled === false`. It explicitly names the `WEBHOOK_BASE_URL` env var.
  - Added `reconnectMutation` wired to `reconnectRepo`. Per-row **Reconnect** button (data-testid `reconnect-repo-<fullName>`) appears only when `webhookRegistrationEnabled === true` AND the row's `syncStatus === 'disconnected'`. The button is placed before Scan/Remove.
  - Added an `actionError` banner (data-testid `repo-action-error`) that surfaces the structured error from failed reconnect attempts; dismissable. This plays the role of the "toast" the issue asks for — the web app has no toast library today, so I used the same inline-alert pattern the rest of this page already uses.
- `src/__tests__/components/Repositories.test.tsx`: updated the `fetchSyncedRepos` mock to include `webhookRegistrationEnabled: true` (matching the new response shape), and added a default `reconnectRepo` mock. Existing 4 tests still pass unmodified.

## Assumptions

- **"Response ... or a sibling endpoint"**: The issue says the flag can live on `GET /api/integrations/:id/github/repos` *or* a sibling. The Repositories page already reads `GET /:id/github/synced-repos` (not `/repos`), so I added the flag to that endpoint to avoid an extra round-trip. If a future consumer reads `/github/repos` directly and needs the flag, it's a two-line add.
- **Reconnect auth level**: I gated the new endpoint on `minimumRole: 'admin'` (same as `PUT /repos` and the existing `DELETE /repos/:repoName`). A disconnected repo is recoverable by any admin.
- **No toast library**: The issue says "UI shows a toast with that message instead of silently failing." The web app currently has no toast library (`grep -rn toast apps/web/src` → zero matches). I used an inline red alert card with a dismiss button, consistent with the existing error pattern in `CreateRepoModal`. If a toast library lands later, swapping `setActionError` for `toast.error(...)` is a one-liner.
- **"Sync disabled" badge copy**: The issue's "Notes for the implementer" suggests changing the badge when the server-wide flag is off. I did the full swap: when `webhookRegistrationEnabled === false`, every disconnected row renders "Sync disabled" (slate) instead of "Disconnected" (amber). This is purely cosmetic; `syncStatus` on the wire still round-trips as `'disconnected'`.
- **Removal-diff when env is unset**: I kept the delete-webhook loop gated on `webhookRegistrationEnabled`. When the env is off there's nothing server-side to delete (webhookIds is empty by construction), so looping is dead work. Selected repos are still persisted regardless, so the user can still manage their list while sync is disabled.
- **PUT response shape is additive**: `{ ok: true }` is still present; `webhookRegistrationEnabled`, `failed`, `skipped` are additions. Existing callers that only read `.ok` keep working (verified: `RepoPickerModal` discards the response).
- **Startup warning location**: I put it at the top of `buildApp()` rather than in `index.ts` so the warning also appears during test runs (tests also use `buildApp()`). This is intentional — it makes the behavior observable in CI logs if someone ever runs tests with an env file that has this wrong.
