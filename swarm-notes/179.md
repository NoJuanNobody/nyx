# Ticket #179 — Recall.ai Webhook Endpoint

## What was implemented

- **`apps/api/src/routes/voice-webhooks.ts`** — New Fastify plugin with `POST /webhooks/recall` route handling two Recall.ai event types:
  - `bot.status_change` — Maps Recall statuses (joining, in_meeting, done, fatal) to internal CallState (connecting, in_call, ended, error) and updates session via call integration service
  - `bot.transcription` — Extracts text from word arrays and forwards to `meetingIntelligenceService.processTranscript()`
  - Optional HMAC-SHA256 signature verification via `RECALL_AI_WEBHOOK_SECRET` env var
  - Always returns 200 OK quickly (webhook best practice)

- **Bot ID mapping** — Exported `registerBotSession(botId, sessionId)` and `getSessionForBot(botId)` functions for the Recall adapter (ticket #178) to call when creating bots

- **`apps/api/src/services/voice/call-integration.service.ts`** — Added `updateSessionState(sessionId, state)` method for external state updates (creates session if not found)

- **`apps/api/src/app.ts`** — Registered `voiceWebhookRoutes` at prefix `/api/voice`

## Tests

- 22 unit tests covering: bot session mapping, request validation, signature verification (valid/invalid/missing), all 4 status mappings, unknown statuses, missing sessions, transcription forwarding, empty transcripts, error resilience, and unknown event types

## Environment variable needed

- `RECALL_AI_WEBHOOK_SECRET` (optional) — Set in Railway to enable HMAC-SHA256 signature verification on incoming webhooks from Recall.ai
