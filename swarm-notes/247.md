# Ticket #247: Fix AI ticket generation to produce code implementation tickets

## What changed

Updated three ticket-generation prompts in `apps/api/src/services/ai.service.ts` to explicitly instruct the AI to generate code implementation tickets instead of documentation tasks.

### Functions modified

1. **`generateTicketFromDiff`** — Replaced generic "ticket generator" system prompt with explicit instructions to generate code implementation work. Added good/bad title examples. Updated fallback title from "Update implementation to match spec changes" to "Implement code changes to match spec updates".

2. **`analyzeChangesForTickets`** — Changed role from "change analyst for a documentation platform" to "change analyst for a software engineering team". Added critical rules requiring tickets describe actionable engineering work.

3. **`generateBulkTicketSuggestions`** — Changed role from "ticket suggestion engine for a documentation platform" to "ticket suggestion engine for a software engineering team". Added critical rules with good/bad examples. Removed "documentation" from the suggested labels list. Updated stage-specific focus strings:
   - `conception/definition` stage: now guides toward code solutions (prototypes, validation logic, API endpoints)
   - `execution` stage: changed from "documentation updates" to "code fixes to bring implementation back in sync with specs"

## What was NOT changed

- No changes to `generateDocument`, `editDocument`, `bootstrapDocsFromCode`, or other non-ticket AI functions
- No schema or migration changes
- No test changes needed (prompt strings are not unit-tested; API tests pass)

## Pre-existing test failures

3 web component tests were already failing before this change (ClaudeInsightCard, FileTreeFolderSuggestions, RecentDocuments) — all timeout-related, unrelated to AI service prompts.
