# Issue #266: New repository button doesn't refresh repositories list after creation

## Root Cause

The `POST /:id/github/repos/create` endpoint in `apps/api/src/routes/integrations.ts` created the repo on GitHub but never added it to the integration's `selectedRepos` config or registered a webhook. The `GET /synced-repos` endpoint only returns repos listed in `selectedRepos`, so the newly created repo was invisible.

## Changes

### `apps/api/src/routes/integrations.ts`

After `githubService.createRepo()` succeeds, the endpoint now:

1. Reads current `selectedRepos`, `webhookIds`, and `webhookSecret` from integration config
2. Builds a new repo entry `{ owner, name, fullName }` from the GitHub API response's `full_name` field
3. Appends to `selectedRepos` (skips if already present)
4. Registers a webhook via `githubService.createWebhook()` (same pattern as the PUT handler)
5. Stores the webhook ID in `webhookIds`
6. Updates integration config in DB via `db.update(integrations).set(...)`

Webhook registration is wrapped in try/catch so the repo is still added to `selectedRepos` even if webhook creation fails.

### `apps/api/src/__tests__/routes/github-create-repo.test.ts`

Added 3 new tests:
- Verifies created repo is added to `selectedRepos` and webhook is registered
- Verifies repo is still added when webhook registration fails
- Verifies no duplicate entry when repo is already in `selectedRepos`

## No Frontend Changes

The existing `onCreated` callback already invalidates `synced-repos` and `integrations` queries. Once the backend adds the repo to `selectedRepos`, the refetch includes it automatically.
