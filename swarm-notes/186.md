# Ticket #186 — PCB Design Documentation Support

## What was done

1. **PCB Parser Service** (`apps/api/src/services/pcb-parser.service.ts`)
   - `parsePCBFile(buffer, fileName)` — extracts metadata from KiCad (.kicad_pcb) and Gerber (.gbr) files: layer count, component count, board dimensions, layer names, and raw properties.
   - `extractBOM(buffer, fileName)` — extracts Bill of Materials from KiCad files with deduplication by value+footprint. Returns array of `{ reference, value, footprint, quantity }`.

2. **PCB Routes** (`apps/api/src/routes/pcb.ts`)
   - `POST /api/documents/:id/pcb` — accepts PCB file upload (multipart, 50MB limit), parses metadata, stores as document attachment metadata in the document's `metadata` JSON field. Requires editor+ role.
   - `GET /api/documents/:id/pcb` — retrieves stored PCB metadata for a document. Requires viewer+ role.

3. **Route Registration** (`apps/api/src/app.ts`)
   - Registered `pcbRoutes` with prefix `/api/documents`.

4. **Tests** (`apps/api/src/services/__tests__/pcb-parser.service.test.ts`)
   - 21 unit tests covering KiCad parsing, Gerber parsing, unknown formats, empty files, BOM extraction, deduplication, and edge cases. All pass.

## What was not done

- Actual PCB board rendering/visualization (noted as follow-up in the ticket).
- No schema migration needed — PCB metadata is stored in the existing `metadata` JSONB column on documents.
