## Ticket #87 — Chaos Ingestion: raw input -> structured spec

### What was built

**Backend:**
- `apps/api/src/services/intake.service.ts` — AI service with `processRawInput()` and `processWithClarifications()` that call Claude to transform raw text into structured specs (title, user story, acceptance criteria, edge cases, open questions, confidence level, markdown)
- `apps/api/src/routes/intake.ts` — Three endpoints: `POST /api/intake/process`, `POST /api/intake/clarify`, `GET /api/intake/history`
- `apps/api/src/db/schema.ts` — Added `intakeSessions` table
- `apps/api/drizzle/0010_intake_sessions.sql` — Migration for the new table
- `apps/api/src/app.ts` — Registered intake routes at `/api/intake`

**Frontend:**
- `apps/web/src/pages/IntakePage.tsx` — Full intake workspace with textarea input, processing state, clarification flow (when confidence is low), result display, and "Save as Document" action
- `apps/web/src/lib/api.ts` — Added `processIntake()`, `clarifyIntake()`, `fetchIntakeHistory()` client functions plus `IntakeSpec` and `IntakeSession` types
- `apps/web/src/App.tsx` — Added `/intake` route
- `apps/web/src/components/Sidebar.tsx` — Added "Intake" sidebar link with sparkle icon

### Patterns followed
- AI service follows existing `ai.service.ts` pattern (same Anthropic client init, MODEL constant, JSON parsing with fallback)
- Route follows existing Fastify plugin pattern with auth check via `request.user`
- Frontend uses same `request<T>()` utility from `api.ts`
- All data-testid attributes added for E2E testability

### What was skipped
- Unit tests for intake service and route (governance requires tests; should be added as follow-up)
- E2E tests for the intake page flow
- The `fetchIntakeHistory` is wired in the API client but there's no history UI — could be added later
