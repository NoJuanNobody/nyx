# Ticket #259 — Zod input validation (Phase 1)

## What was done

### Phase 1 scope: AI routes, intake routes, webhook routes

1. **Created shared Zod schemas** in `packages/shared/src/schemas/`:
   - `ai.ts` — 16 schemas for all AI route endpoints
   - `intake.ts` — 3 schemas (process, clarify, history query)
   - `webhook.ts` — 3 schemas (push, issues, issue_comment payloads)

2. **Added global ZodError handler** in `apps/api/src/app.ts`:
   - Returns 400 with `{ error: 'Validation failed', details: [...] }` format
   - Each detail includes `path` and `message` for client-side field mapping

3. **Applied Zod `.parse()` to all 16 AI endpoints** in `apps/api/src/routes/ai.ts`:
   - Replaced all `request.body as { ... }` casts with schema `.parse()` calls
   - Removed manual `if (!field)` validation blocks (Zod handles this)

4. **Applied Zod to intake routes** in `apps/api/src/routes/intake.ts`:
   - POST `/process`, POST `/clarify`, GET `/history` (query param validation)

5. **Applied Zod to webhook routes** in `apps/api/src/routes/webhooks.ts`:
   - Validates payload structure for push, issues, and issue_comment events
   - Signature verification remains unchanged (runs before body validation)

6. **Updated AI route tests** (`apps/api/src/__tests__/routes/ai.test.ts`):
   - Added ZodError handler to test `buildApp()` helper
   - Updated error message assertions to match new `'Validation failed'` format

## Not in scope (Phase 2)

- Query parameter and URL param validation for non-intake routes
- Request header validation
- Response schema validation
