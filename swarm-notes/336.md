# Ticket #336 -- Collapse approve-changes diff to single column on mobile

## Problem
`DiffView` rendered every row as a fixed two-column flex layout regardless of viewport, so on a 375px phone the AI approve-changes diff was unreadable.

## Changes

1. **`apps/web/src/components/DiffView.tsx`** -- Refactored rendering into two
   sub-components, `SideBySideRows` (existing two-column layout) and
   `UnifiedRows` (new single-column layout). Both consume the same diff array
   produced by the existing `computeDiff` function (no algorithm changes).
   - `UnifiedRows` renders each `DiffLine` once with a leading marker
     (`+`, `-`, or space), `bg-green-100/red-100` backgrounds matching the
     desktop colors, and `text-slate-600` for equal lines. Lines soft-wrap
     via `whitespace-pre-wrap break-words`.
   - The header now adapts: a compact pill row
     ("- Current / + AI suggestion") on mobile, the existing two-column
     `Old`/`New` labels on desktop.
   - Breakpoint switching is purely Tailwind responsive classes
     (`md:hidden` and `hidden md:block` / `hidden md:flex`) -- no
     `window.innerWidth` and no JS media queries, so SSR/hydration and live
     resize both work.
   - Added `data-testid` hooks (`diff-view-unified`, `diff-view-side`,
     `diff-row-unified`, `diff-row-side`, `diff-header-unified`,
     `diff-header-side`) so the responsive behaviour is observable from
     Playwright.

2. **`apps/web/src/components/AIEditReview.tsx`** -- The toolbar already used
   flex but the children could not wrap. Added `flex-wrap` and `gap-y-2`
   on the toolbar row plus `flex-wrap` on the inner left/right groups so
   that on a 375px viewport the Diff/Edit toggle, Reject, and Approve
   controls all stay tappable without horizontal page overflow. Also
   added a `data-testid="ai-edit-review"` hook.

3. **`e2e/diff-view-responsive.spec.ts`** (new) -- Two Playwright tests:
   - **375x812 (iPhone 14)**: opens a doc, expands the AI advisor, fires
     the AI edit through the mocked `/ai/edit-document` route, and asserts
     that `[data-testid="diff-view-unified"]` is visible while
     `[data-testid="diff-view-side"]` is hidden, that there is at least one
     unified row in DOM, that no side-by-side row is visible (via
     `getBoundingClientRect`), that the first unified row has exactly one
     `.flex-1` child, that `document.documentElement.scrollWidth <= 375`
     (no horizontal overflow), and that the Diff / Edit / Reject / Approve
     toolbar buttons are all visible.
   - **1280x800**: opens the same flow at desktop width and asserts the
     reverse -- side-by-side container visible, unified container hidden,
     two-column header visible, each side-by-side row has exactly two
     `.flex-1` children, and the two children are horizontally adjacent
     (different `x`, same `y`).
