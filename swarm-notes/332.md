# Ticket 332 — Remove marketplace feature and all related code

## What changed

Removed the template marketplace feature end-to-end across web, api,
cli, and database. The feature (template/workflow/prompt listings,
reviews, purchases, and the `from-template` document creation flow) is
no longer part of Nyx's product direction, so all of its code, routes,
tables, types, and CLI commands were deleted in one pass.

## Files modified

### Deleted
- `apps/web/src/pages/Marketplace.tsx`
- `apps/api/src/routes/marketplace.ts`

### Backend (`apps/api`)
- `src/app.ts` — removed `marketplaceRoutes` import and its
  `/api/marketplace` registration
- `src/db/schema.ts` — removed `marketplaceListings` and
  `marketplaceReviews` tables, plus their `listingTypeEnum` and
  `listingPriceTypeEnum` enums, and the empty
  "Community Marketplace" section comment
- `src/routes/documents.ts` — removed the `marketplaceListings`
  import, the unused `and`/`sql` imports it pulled in, and the entire
  `POST /api/documents/from-template` handler (its only caller was

- `src/__tests__/routes/documents.test.ts` — deleted the
  `POST /api/documents/from-template` describe block (5 tests)
- `drizzle/0015_drop_marketplace.sql` — NEW hand-written migration
  that drops `marketplace_reviews`, `marketplace_listings`, and the
  `listing_type` / `listing_price_type` enums. See "Assumptions"
  below for why this was hand-written rather than generated.

### Frontend (`apps/web`)
- `src/App.tsx` — removed `Marketplace` import and `/marketplace` route
- `src/components/Sidebar.tsx` — removed the marketplace nav entry
- `src/lib/api.ts` — removed `MarketplaceListing`, `MarketplaceReview`
  types, `fetchMarketplaceListings`, `fetchMarketplaceListing`,
  `createMarketplaceListing`, `downloadMarketplaceListing`,
  `reviewMarketplaceListing`, `purchaseMarketplaceListing`, and
  `createDocumentFromTemplate` (the last was only used by

### CLI (`packages/cli`)
- `src/index.ts` — removed `marketplace` from the help text and from
  the lazy command registry (`templates` remains on its own)
- `src/commands/templates.ts` — removed the `MarketplaceListing`
  interface and the entire `registerMarketplaceCommand` export
  (`registerTemplatesCommand` retained)

## Assumptions

1. **Hand-written drop migration (`0015_drop_marketplace.sql`)** —
   the ticket's playbook asked me to run
   `pnpm --filter api db:generate` so drizzle-kit would produce the
   migration. I tried that first. Drizzle-kit generated
   `0009_lush_terrax.sql` (not `0015`) because the drizzle snapshot
   metadata in `apps/api/drizzle/meta/` is severely stale — the
   newest snapshot is `0008_snapshot.json` and the `_journal.json`
   entries also stop at `0008_document_lifecycle`, even though
   real migrations exist up through `0014_conversation_id.sql`.
   The auto-generated file was a wildly out-of-scope migration that
   recreated huge parts of the schema (matching the drift between the
   snapshot and the live schema), which is not something this ticket
   should introduce. I reverted the generated file, restored
   `_journal.json`, and wrote `0015_drop_marketplace.sql` by hand to
   match the pattern already used by `0009_custom_templates.sql`
   through `0014_conversation_id.sql`, which are all hand-written.
   The new migration is minimal and surgical: two `DROP TABLE IF
   EXISTS` statements plus two `DROP TYPE IF EXISTS` cleanups. The
   snapshot metadata drift is a pre-existing repo condition that is
   out of scope to repair here.

2. **`createDocumentFromTemplate` helper was removed** — its only
   caller was `Marketplace.tsx`, and the API route it called
   (`POST /api/documents/from-template`) only existed to serve the
   marketplace. With both gone, the helper is dead code. This matches
   the ticket's stated assumption that the `from-template` flow is
   being removed entirely.

3. **`makeUser` import in `documents.test.ts`** — left untouched. It
   was already imported but unused before this change, so removing it
   now would be a surgical violation (the change would be unrelated
   to removing marketplace). TypeScript does not error on unused
   imports in this repo (no `noUnusedLocals`).

4. **`0013_multi_lifecycle.sql` still references `marketplace_listings`**
   via an `ALTER TABLE "marketplace_listings" ALTER COLUMN "stage"
   TYPE text;` — this is a historical migration that already ran in
   every environment and must remain immutable. The new `0015` drop
   runs after it and removes the table cleanly.

5. **`.github/workflows/claude-code-review.yml` contains the string
   `plugin_marketplaces`** — unrelated (Claude Code plugin system),
   left alone.

6. **`nyx-conference-itinerary-2026.md` mentions "marketplace"** —
   unrelated commentary about GitHub's partner marketplace, left alone.

## Governance conflicts

None. Change stays within scope (marketplace removal), no new markdown
files created outside of this swarm-note, no secrets touched, no tests
skipped (marketplace test cases were deleted, not skipped, per ticket).

## Follow-up items

1. **Drizzle snapshot metadata is stale.** The `apps/api/drizzle/meta/`
   snapshots only go up to `0008` even though migrations run through
   `0014`. This means `pnpm --filter api db:generate` cannot produce
   correct migrations today — it always tries to regenerate everything
   since `0008`. Worth opening a separate ticket to regenerate the
   snapshot + journal in sync with the current schema so future
   migrations can use `db:generate` normally.

2. **`meeting-quality.test.ts` is flaky.** First run of `pnpm test`
   failed with a 10s timeout on
   `analyzeMeetingNoteQuality > should return score, suggestions, and
   meeting metrics`. Second run passed. Unrelated to this ticket but
   worth flagging.

3. **Staging/prod data migration.** Dropping `marketplace_listings`
   and `marketplace_reviews` is destructive. Before running
   `0015_drop_marketplace.sql` against staging/prod, confirm there is
   no real marketplace data that needs exporting first. The ticket
   calls this out as an assumption to confirm pre-merge.

4. **`templates` CLI command retained.** Only the `marketplace`
   subcommand group was removed; the template CRUD commands
   (`list`, `get`, `create`) are unchanged and still hit
   `/api/templates`.
