# Ticket #150: Real-Time Transcription and Semantic Parsing

## What was done

### New files created
- `packages/shared/src/types/meeting-intelligence.ts` — Zod schemas and TypeScript types for TranscriptSegment, Decision, ActionItem, CodeReference, OpenQuestion, MeetingIntelligence, and ParsedIntelligence
- `apps/api/src/services/voice/diarization.service.ts` — MVP speaker diarization that detects "Speaker X:" colon patterns, "[Speaker]" bracket patterns, or falls back to newline-based alternation
- `apps/api/src/services/voice/semantic-parser.service.ts` — AI-powered extraction using Claude API (follows ai.service.ts pattern with code-fence stripping, JSON extraction, graceful fallbacks)
- `apps/api/src/services/voice/meeting-intelligence.service.ts` — Orchestrator: diarizes transcript, runs semantic parser, stores results in-memory Map by sessionId
- `apps/api/src/routes/voice-transcription.ts` — Three endpoints: POST /transcribe (text or audio), GET /intelligence/:sessionId, POST /parse
- `apps/api/src/services/voice/__tests__/semantic-parser.service.test.ts` — 7 tests covering valid parse, code-fence stripping, empty input, malformed JSON, API errors, partial responses, prose-embedded JSON
- `apps/api/src/services/voice/__tests__/meeting-intelligence.service.test.ts` — 7 tests covering processTranscript, storage/retrieval, error handling, audio buffer flow, session overwrite, UUID generation

### Files modified
- `packages/shared/src/index.ts` — Added meeting-intelligence export
- `apps/api/src/app.ts` — Imported and registered voiceTranscriptionRoutes at /api/voice

## Test results
14/14 tests passing.

## Design decisions
- Followed the existing ai.service.ts pattern for Claude API calls: Anthropic SDK, code-fence stripping regex, JSON extraction with fallback
- Used provider-agnostic interface: the semantic parser returns ParsedIntelligence type; the AI provider can be swapped
- Diarization service is a stub designed for replacement — detects speaker label patterns in text, not real audio diarization
- In-memory Map for session storage (sufficient for MVP; can be swapped for DB persistence later)
- Audio processing delegates to existing transcriptionService.transcribeAudio
