# 350 — Generate agent suggestions from document + conversation context

## Summary

Replaced the hardcoded agent-suggestion chips in `UnifiedAIPanel` with
model-generated, context-aware prompts. The empty-state chips now reflect
the current document's title / stage / content preview / connected
codebase, and the post-session follow-up chips reflect what the agent
actually did (last user prompt, tool-call summary, final output,
`incomplete` flag from #349).

Branch: `swarm/350`, base: `main@1f2c64d`.

## Files changed

### Shared schema
- `packages/shared/src/schemas/ai.ts` — added `suggestionsBody` zod schema
  (required: `kind`, `documentId`, `teamId`; optional: `content`, `stage`,
  `history`, `toolCallSummary`, `finalResult`, `incomplete`).

### Backend service
- `apps/api/src/services/ai.service.ts` — added `generateSuggestions({ kind, ... })`
  method. Uses `MODEL_FAST` (Haiku), not `MODEL` (Sonnet). Two system prompt
  variants (pre-session vs post-session), both include the explicit
  anti-boilerplate instruction from the issue:
  > "Do NOT produce generic prompts like 'Add error handling', 'Rewrite the
  > intro', or 'Add more detail'. Each suggestion must name a specific concept
  > from the provided document or conversation."
  Parses JSON array output (tolerating code-fence wrappers and leading prose),
  trims to exactly 3 items, and returns `[]` on any failure — malformed JSON,
  non-array, empty strings, thrown errors.

### Backend route
- `apps/api/src/routes/ai.ts` — added `POST /api/ai/suggestions`:
  - Parses `suggestionsBody` via zod → 400 on validation failure.
  - Loads the document scoped to the team; returns `{ suggestions: [] }` if
    the doc isn't found (doesn't leak existence).
  - **Pre-session:** optionally looks up the team's GitHub integration, pulls
    the `repoFullName` from `config.selectedRepos[0].fullName` (or
    `owner`/`repo` fallback), and calls
    `codeEmbeddingService.fetchRelevantCodeForDocument` from #343 for
    relevant code chunks. All codebase-retrieval failure modes are non-fatal
    — the route logs a warning and continues without the hint.
  - **Post-session:** passes `history`, `toolCallSummary`, `finalResult`, and
    `incomplete` through to the service.
  - **Failure mode:** on any service throw or when the service returns
    fewer than 3 suggestions, returns `HTTP 200 { suggestions: [] }` so the
    frontend falls back gracefully.
  - Rate limit: `{ max: 20, timeWindow: '1 minute' }` — matches the other
    AI endpoints.

### Frontend client
- `apps/web/src/lib/api.ts` — added `fetchAISuggestions(payload)` helper
  with typed `AISuggestionsPayload` and `AISuggestionKind`.

### Frontend store + agent stream
- `apps/web/src/lib/agent-stream.ts` — added `incomplete?: boolean` to the
  `done` event type so the `incomplete` flag from #349 can reach the UI.
- `apps/web/src/stores/aiChat.store.ts`:
  - Added `incomplete: boolean` and `completionCounter: number` to
    `AIChatSession` so `useEffect` can fire once per completed session
    without re-firing on re-renders or panel switches.
  - Added `markCompleted(documentId, incomplete)` action that sets status to
    `'completed'`, stores the `incomplete` flag, and bumps the counter.
  - `useAIChatSession` exposes `incomplete`, `completionCounter`, and
    `markCompleted`.

### Frontend component
- `apps/web/src/components/UnifiedAIPanel.tsx`:
  - **Pre-session chips:** replaced the hardcoded three-branch ternary at
    lines 328-337 with a `useQuery` keyed on
    `['ai-suggestions', 'pre-session', documentId, contentHash, stage]`.
    `contentHash` is a cheap, stable `"${length}-${charCodeAt(0)}"` over
    the first 500 chars so small edits don't thrash the query. A `useMemo`
    builds the static `STAGE_SUGGESTIONS` fallback; while the query is
    loading / errors / resolves empty, the fallback is rendered instead.
    The query is disabled when the document hasn't been saved yet
    (`!documentId`), for new empty documents (the `isNewDocument && !content.trim()`
    path), or when the panel isn't empty.
  - **`done` event handler:** now calls `markCompleted(event.incomplete ?? false)`
    instead of just `setStatus('completed')`.
  - **Post-session chips:** added a `useEffect` keyed on `completionCounter`
    + `status` that runs once per completed run, builds a tool-call summary
    by walking `messages` (counting each `tool_call.entry.toolName`),
    extracts the last user prompt and last assistant text, and calls
    `fetchAISuggestions('post-session', ...)` with `incomplete` from the
    store. Uses a `lastHandledCompletionRef` to ensure the effect fires
    exactly once per completion. Fetched suggestions override the static
    `wf.postSessionSuggestions` list; on empty/error, the static fallback
    renders.
  - Did NOT delete `STAGE_SUGGESTIONS` (stages.ts / lifecycles.ts) or
    `postSessionSuggestions` (agent/workflows.ts) — both remain as the
    graceful-degradation fallback.

### Tests

  - Valid JSON array of 3 strings → returns those 3.
  - 5 items → trimmed to first 3.
  - Malformed JSON → `[]`.
  - Code-fence wrapper → stripped and parsed.
  - Model throws → `[]`.
  - Pre-session system prompt includes anti-boilerplate + uses Haiku +
    user prompt includes title/stage/preview.
  - Post-session system prompt includes anti-boilerplate + user prompt
    includes last user content, compressed tool-call summary
    (`search_code×3`), final output, and "terminated early" note when
    `incomplete: true`.
  - Pre-session with `codebaseHint` → repo name and top file paths appear
    in the user prompt.
- `apps/api/src/__tests__/routes/ai.test.ts` — added a new
  `describe('POST /api/ai/suggestions', ...)` block with 7 tests:
  - Pre-session returns 3 suggestions from the mocked service.
  - Pre-session with a GitHub integration exercises
    `fetchRelevantCodeForDocument` and passes a `codebaseHint` into the
    service containing `repoFullName: 'acme/backend'` and 2 chunks.
  - Service throw → `200 { suggestions: [] }`.
  - Service returns fewer than 3 → `200 { suggestions: [] }`.
  - Post-session passes `history`, `toolCallSummary`, `finalResult`, and
    `incomplete: true` through to the service unchanged.
  - Missing required fields → 400.
  - Document not found → `200 { suggestions: [] }` and service is not called.
  - Added `integrations` to the mocked `db/schema.js` module and `and` to
    the mocked `drizzle-orm` module to keep the existing tests happy.
- `apps/web/src/__tests__/components/UnifiedAIPanel.test.tsx` — added
  3 RTL tests:
  - Pre-session: `fetchAISuggestions` resolves with 3 custom strings →
    the empty state renders the custom strings.
  - Pre-session: `fetchAISuggestions` rejects → the static fallback is
    rendered (`'Add a section about error handling'` and siblings).
  - Pre-session: `fetchAISuggestions` returns `{ suggestions: [] }` →
    static fallback is rendered.
  - Defaulted the mock to `{ suggestions: [] }` so unrelated pre-existing
    tests don't trigger React Query undefined-data warnings.
