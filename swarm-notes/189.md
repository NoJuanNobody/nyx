# Ticket #189 — Stripe Integration

## What was done

1. **Config**: Added `STRIPE_PUBLISHABLE_KEY` as optional string to `apps/api/src/lib/config.ts`. `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` already existed.

2. **Stripe service** (`apps/api/src/services/stripe.service.ts`): Updated the existing service to support **stub mode** — when `STRIPE_SECRET_KEY` is not set, all methods return mock URLs/IDs instead of throwing. This enables local development without Stripe credentials. Functions:
   - `getOrCreateCustomer(teamId, teamName, email)` — finds or creates a Stripe customer
   - `createCheckoutSession(customerId, priceId, teamId, successUrl, cancelUrl)` — creates checkout session (stub returns mock URL)
   - `createPortalSession(customerId, returnUrl)` — creates billing portal session (stub returns mock URL)
   - `handleWebhookEvent(payload, signature)` — processes `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`
   - `getPriceId(plan)` — maps plan names to Stripe price IDs

3. **Schema**: Added `stripe_customers` table to `apps/api/src/db/schema.ts` with columns: id, userId, stripeCustomerId (unique), subscriptionId (nullable), plan (default 'free'), planExpiresAt (nullable), createdAt, updatedAt.

4. **Billing routes** (`apps/api/src/routes/billing.ts`):
   - `POST /api/billing/checkout` — create checkout session
   - `POST /api/billing/portal` — create portal session
   - `POST /api/billing/webhooks/stripe` — webhook handler with raw body for signature verification

5. **Route registration**: Added `billingRoutes` to `apps/api/src/app.ts` at `/api/billing`.

6. **Tests** (`apps/api/src/services/__tests__/stripe.service.test.ts`): 11 tests covering:
   - `getPriceId` for known and unknown plans
   - Stub-mode checkout, portal, and customer creation
   - Webhook event processing for all three event types
   - Unhandled event type passthrough
   - Error when webhook secret is missing

## Notes

- The existing `subscriptions` route (`apps/api/src/routes/subscriptions.ts`) already had checkout/portal/webhook endpoints at `/api/subscriptions/*`. The new billing routes provide the same at `/api/billing/*` as specified in the ticket. Both route sets use the same stripe service.
- Pre-existing test failures in `voice-webhooks.test.ts`, `recall-adapter.test.ts`, `app.test.ts`, and `smoke.test.ts` are unrelated to this change (voice route `@nyx/shared` resolution issue and recall API URL changes).

## Environment setup needed

To use Stripe in production, set the following environment variables:
- `STRIPE_SECRET_KEY` — Stripe secret API key (from Stripe Dashboard > Developers > API keys)
- `STRIPE_PUBLISHABLE_KEY` — Stripe publishable API key
- `STRIPE_WEBHOOK_SECRET` — Stripe webhook signing secret (from Stripe Dashboard > Developers > Webhooks)
- `STRIPE_PRICE_PRO` — Stripe Price ID for the Pro plan
- `STRIPE_PRICE_TEAM` — Stripe Price ID for the Team plan
