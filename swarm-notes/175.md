# Ticket #175 — Add loading indicator when clicking seed definition

## What changed

Added a loading overlay to the FileTree (explorer sidebar) that appears while a seed definition operation is in progress, preventing users from accidentally clicking on files and overwriting documents.

## Files modified

- `apps/web/src/stores/ui.store.ts` — Added `seeding` and `setSeeding` to the shared UI store so the seeding state can be shared between DocumentEditor and FileTree
- `apps/web/src/pages/DocumentEditor.tsx` — Replaced local `seeding` state with the shared UI store's `seeding`/`setSeeding`
- `apps/web/src/components/FileTree.tsx` — Added a translucent overlay with animated spinner that covers the entire FileTree when `seeding` is true, blocking all user interaction
- `apps/web/src/__tests__/stores/ui.store.test.ts` — Added test for seeding state management
- `apps/web/src/__tests__/components/FileTreeSeedingOverlay.test.tsx` — New test file verifying overlay visibility based on seeding state

## Assumptions

- The ticket refers to the "Seed [Next Stage]" button in the DocumentEditor toolbar. This is the only "seed definition" mechanism in the codebase.
- A CSS spinner (SVG + Tailwind `animate-spin`) is sufficient — no external GIF asset needed.
- The overlay blocks pointer events on the entire FileTree panel during seeding, which effectively prevents file navigation.
