# #346 — Move app routes under /app prefix and expose landing at /

## Summary
Restructured `apps/web/src/App.tsx` so the authenticated app lives under a `/app/*` namespace and `/` is unambiguously the Landing page (for anonymous visitors) or a redirect to `/app/dashboard` (for authenticated visitors). Added legacy redirects for every pre-existing top-level app route so bookmarks keep working, and updated every internal navigation site in the web app, API OAuth callbacks, and all e2e specs.

## Routing changes (`apps/web/src/App.tsx`)
- `/` → `<RootRoute />` which renders `<Landing />` for anonymous Clerk users and `<Navigate to="/app/dashboard" replace />` for authenticated or dev-mode visitors.
- `/app` → nested `<Route>` under `<AuthGuard />` + `<Layout />`; `index` redirects to `/app/dashboard`.
- `/app/dashboard`, `/app/documents/:id`, `/app/documents/:id/trace`, `/app/settings`, `/app/board`, `/app/repositories`, `/app/intake`, `/app/sprint`, `/app/operations`, `/app/getting-started` — moved under the parent as children with relative paths.
- In-app redirects (`/app/agent-map`, `/app/observability`, `/app/voice`, `/app/admin/documents`) point at `/app/operations?tab=...` and `/app/dashboard`.
- `LandingOrDashboard` helper deleted as dead code.
- `/landing` → `<Navigate to="/" replace />`.
- New helper components:
  - `LegacyRedirect({ to })` — reads `useLocation().search` and appends it so `/dashboard?foo=bar` redirects to `/app/dashboard?foo=bar`.
  - `LegacyDocumentRedirect({ suffix? })` — reads `useParams()` and `useLocation().search`, builds `/app/documents/:id[suffix]?...` target.
- Legacy top-level redirects added: `/dashboard`, `/documents/:id`, `/documents/:id/trace`, `/settings`, `/board`, `/repositories`, `/intake`, `/sprint`, `/operations`, `/getting-started`, plus root-level `/agent-map`, `/observability`, `/voice`, `/admin/documents`.
- No `/documents/:id/preview` redirect (removed in #341).
- No `/marketplace` redirect (removed in #332).

## Query-string preservation
- `LegacyRedirect` and `LegacyDocumentRedirect` both splice `useLocation().search` onto the target URL, so query strings and `?tab=...` fragments survive the redirect.

## E2E specs
- `e2e/fixtures/test-base.ts` — `authenticatedPage` fixture now visits `/app/dashboard`.
- `e2e/fixtures/selectors.ts` — `fileTree.docLink`, `dashboard.docRow`, `dashboard.recentDocs.docItem` updated to the `/app/documents/*` href form.
- Bulk `sed` pass over `e2e/**/*.ts` and `tests/e2e/**/*.ts` to rewrite `'/dashboard'` → `'/app/dashboard'` (and all siblings) in both `'` and `"` quoted forms, plus `\`/documents/${...}\`` template literals. The regex-based `toHaveURL(/\/documents\//)` assertions remain unchanged because they still match `/app/documents/` as a substring.
- `e2e/landing.spec.ts` fully rewritten — `/landing` goto replaced with `/` + a `enableClerkForLanding` helper that patches `import.meta.env.VITE_CLERK_PUBLISHABLE_KEY` in the vite-served JS so `/` renders Landing (dev bypass mode would otherwise redirect `/` straight to `/app/dashboard`). A separate `describe` block uses the existing `authenticatedPage` fixture to assert the dev-mode `/` → `/app/dashboard` redirect.
- **New**: `e2e/app-prefix-routing.spec.ts` covering:
  - Every legacy top-level path (`/dashboard`, `/settings`, `/board`, `/repositories`, `/intake`, `/sprint`, `/operations`, `/getting-started`) redirecting to its `/app/*` equivalent.
  - `/dashboard?foo=bar&baz=qux` preserving both query params.
  - `/documents/:id?highlight=...` redirecting to `/app/documents/:id?highlight=...` (params + query preserved).
  - `/documents/:id/trace` redirecting to `/app/documents/:id/trace`.
  - `/app` (bare) redirecting to `/app/dashboard`.
  - Dev-mode authenticated `/` redirecting to `/app/dashboard`.
  - `/admin/documents`, `/agent-map`, `/observability`, `/voice` legacy redirects.

## What I did not touch (by design)
- `/lifecycle` references (`apps/web/src/pages/AcceptInvite.tsx`, `Dashboard.tsx`, `GettingStarted.tsx`) — that route does not exist in `App.tsx` and is unrelated to the `/app` prefix migration. Pre-existing dead-link behavior is preserved.
- `apps/web/src/lib/api.ts` — uses `/documents`, `/intake`, `/sprint` etc. as API path segments joined to the `BASE = '/api'` prefix, i.e. backend routes (not client-side app routes).
- Backend route definitions (`/api/documents`, `/api/intake`, ...) — out of scope.
- `apps/api/src/routes/voice-documents.ts` and similar — those are `/api/voice/documents/*` API endpoints, not app routes.
- No Vite `base` config change, no Fastify static file change.

## Notes for reviewers
- The e2e bulk rewrite used targeted `sed` patterns (`'/dashboard'`, `"/dashboard"`, `'/dashboard?`, ...) to avoid touching substring references such as `/api/dashboard` or doc comments mentioning `dashboard` as a word.
- `toHaveURL(/\/documents\//)` regex patterns continue to pass because `/app/documents/...` still contains `/documents/` as a substring — they were intentionally left alone.
- `e2e/fixtures/test-base.ts` ~1000-line fixture file was only touched in one place (the `authenticatedPage` goto) — the `/api/documents/...` mock routes are API-side and unchanged.
- The `DocumentEditor.test.tsx` in-memory router was updated to `/app/documents/:id` to keep the test self-consistent with the production routing shape.
- `landing.spec.ts` relies on patching the Vite-served JS response text to flip the `VITE_CLERK_PUBLISHABLE_KEY` env read; this is the mirror of the existing technique used in the old `37.8` test to disable Clerk. It is brittle but matches the established pattern in this repo.
