# Ticket #89 — Sprint Gatekeeper: Linear/Jira sync + trade-off UI

## What was built

### Backend
- **`apps/api/src/services/sprint.service.ts`** — Sprint capacity service with `getSprintCapacity()`, `checkSprintCapacity()`, and `deferTicket()`. Uses mock data for MVP; ready for Jira/Linear integration via TODO markers. Tracks deferred tickets in-memory.
- **`apps/api/src/routes/sprint.ts`** — Three endpoints: `GET /api/sprint/capacity`, `POST /api/sprint/check`, `POST /api/sprint/defer`. All validate required params.
- **`apps/api/src/app.ts`** — Registered sprint routes with `/api` prefix.

### Frontend
- **`apps/web/src/components/SprintGatekeeper.tsx`** — Full trade-off UI with capacity progress bar, ticket list, warning banner at >=80%, checkbox-based deferral, and "Schedule for Next Sprint" option. Uses Tailwind + slate palette matching existing design.
- **`apps/web/src/pages/SprintPage.tsx`** — Page wrapper for the component.
- **`apps/web/src/lib/api.ts`** — Three API client functions: `getSprintCapacity()`, `checkSprintCapacity()`, `deferSprintTicket()`.
- **`apps/web/src/App.tsx`** — Added `/sprint` route.
- **`apps/web/src/components/Sidebar.tsx`** — Added "Sprint" nav link with bar-chart icon.

### Tests (17 total, all passing)
- **`apps/api/src/__tests__/services/sprint.service.test.ts`** — 9 tests covering capacity retrieval, deferral effects, threshold detection, edge cases.
- **`apps/api/src/__tests__/routes/sprint.test.ts`** — 8 tests covering all three endpoints, validation errors, and happy paths.

## What was skipped
- Real Jira/Linear API integration (by design — MVP uses mock data, service has TODO markers for real integration)
- Persistence of deferred tickets (in-memory only; adequate for MVP)
- E2E tests (no existing sprint-related E2E infrastructure to build on)

## Notes
- The `SprintGatekeeper` component is designed to be importable into the ticket creation flow as a pre-check. It's currently exposed as a standalone page at `/sprint` and can be embedded elsewhere.
- Capacity threshold is hardcoded at 80% in the service. Could be made configurable per-team later.
