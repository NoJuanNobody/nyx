# Ticket #289 — CLI: nyx check spec compliance gate

## What was done
- Created `apps/api/src/services/compliance.service.ts` with `checkCompliance(codeContent, teamId, filePath?)` that:
  - Uses `retrieveChunks` to find relevant spec chunks for the given code
  - Sends specs + code to Claude with a structured prompt for per-violation analysis
  - Returns `{ compliant: boolean, violations: Array<{ rule, severity, description, specRef }> }`
- Created `apps/api/src/routes/compliance.ts` with `POST /api/compliance/check` endpoint
  - Accepts `{ code: string, teamId: string, filePath?: string }`
  - Validates inputs, delegates to compliance service
- Registered compliance route in `apps/api/src/app.ts`
- Created `packages/cli/src/commands/check.ts` with `nyx check <file>` command:
  - Reads local file, sends content to compliance endpoint
  - Pretty output with severity icons and violation details
  - JSON output via `--format json`
  - Exit code 1 if any errors (CI-friendly), warnings do not cause non-zero exit
  - `--team-id` option (falls back to env/config)
- Registered `registerCheckCommand` in `packages/cli/src/index.ts`
- Created `packages/cli/src/__tests__/check.test.ts` with 7 unit tests covering:
  - Command registration
  - API call with correct payload
  - Compliant output message
  - Violation pretty-print formatting
  - Exit code 1 on errors
  - No exit code 1 on warnings-only
  - JSON output format

## Build & test status
- `pnpm --filter @nyx/cli build` passes
- All 7 new check tests pass
- Pre-existing test failures in other commands are unrelated
