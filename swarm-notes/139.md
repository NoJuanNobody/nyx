# Ticket #139 — Real-Time Doc Change Notifications for Nyx CLI

## What was built

### Backend: Document changes endpoint
- `apps/api/src/routes/doc-changes.ts` — `GET /api/documents/changes?teamId=X&since=<ISO>&limit=N`
- Queries documents table using Drizzle `gt(documents.updatedAt, sinceDate)`, ordered by most recent first
- Returns `{ changes, since, until }` where `until` is the latest `updatedAt` (cursor for pagination)
- Validates teamId (required), since (required, must be valid ISO-8601), and limit (capped at 200)
- Registered in `apps/api/src/app.ts` under `/api/documents` prefix

### Backend test
- `apps/api/src/__tests__/routes/doc-changes.test.ts` — 7 tests covering validation, data return, empty results, and limit capping

### CLI package (new)
- `packages/cli/` — new workspace package `@nyx/cli` with Commander.js
- `packages/cli/src/lib/api-client.ts` — minimal fetch-based API client using `NYX_API_URL` and `NYX_API_KEY` env vars
- `packages/cli/src/commands/watch.ts` — two commands:
  - `nyx watch --team-id <id> [--interval <s>] [--since <iso>]` — continuous polling with SIGINT cleanup
  - `nyx changes --team-id <id> [--since <iso>] [--limit <n>] [--format json|table]` — one-shot fetch
- `packages/cli/src/index.ts` — entry point with sentinel blocks for future command registration

### CLI test
- `packages/cli/src/__tests__/watch.test.ts` — 7 tests: command registration checks, API call verification, format options, limit passthrough
