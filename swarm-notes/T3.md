# T3: Notification REST API Routes

## What was implemented

Notification REST API routes as a Fastify plugin registered at `/api/notifications`.

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | List notifications with cursor-based pagination, optional `read`, `event_type`, `limit`, `cursor` query params |
| GET | `/unread-count` | Returns `{ count }` for badge polling |
| PATCH | `/:id/read` | Mark single notification as read (sets `readAt = now()`) |
| PATCH | `/read-all` | Mark all user notifications as read |
| DELETE | `/:id` | Delete a single notification |
| GET | `/preferences` | Get all notification preferences for user |
| PUT | `/preferences` | Bulk replace all preferences (array body) |
| PATCH | `/preferences/:event_type` | Upsert single event type preference |

### Pagination

Cursor-based on `createdAt DESC`. The list endpoint fetches `limit + 1` rows; if the extra row exists, it pops it and returns the last item's `createdAt` as `nextCursor`. Default limit is 20, max 50.

### Auth

All routes check `request.user?.id` and return 401 if missing, following the existing codebase pattern.
