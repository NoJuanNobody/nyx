# Ticket #131 — Podcast Script Generation from Docs

## What was built

### Backend
- **`apps/api/src/routes/podcast.ts`** — Two endpoints:
  - `POST /api/podcast/generate` — accepts `{ documentIds, teamId, title? }`, calls AI service, stores script in memory, returns full script object
  - `GET /api/podcast/scripts?teamId=X` — lists generated scripts filtered by team
- **`apps/api/src/services/ai.service.ts`** — Added `generatePodcastScript()` method that uses Claude to generate a conversational script between Host A and Host B, plus quality assessment
- **`apps/api/src/app.ts`** — Registered `podcastRoutes` with prefix `/api`

### Backend tests
- **`apps/api/src/__tests__/routes/podcast.test.ts`** — 8 tests covering generate and list endpoints, validation, and filtering

### CLI package (new: `packages/cli`)
- Scaffolded full CLI package with `commander`, TypeScript, vitest
- **`packages/cli/src/commands/podcast.ts`** — Two subcommands:
  - `nyx podcast generate <doc-ids...> --team-id <id> [--title <title>] [--format json|table]`
  - `nyx podcast list --team-id <id> [--format json|table]`
- **`packages/cli/src/lib/api.ts`** — Shared API request helper (uses `NYX_API_URL` env or defaults to `localhost:3001`)
- **`packages/cli/src/index.ts`** — Entry point with sentinel comment blocks for future command registration

### CLI tests
- **`packages/cli/src/__tests__/podcast.test.ts`** — 6 tests covering generate, list, JSON format, empty results, and error handling

## Patterns followed
- In-memory storage for MVP (same as sprint service)
- AI service uses `requireClient()` + Claude with system prompt returning JSON
- Route test pattern: `vi.hoisted` mock + Fastify inject
- CLI uses `commander` with subcommands and `--format` flag
