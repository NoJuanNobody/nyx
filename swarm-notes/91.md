# Ticket #91 — Slack Interception: Passive Intake from Team Channels

## What was built

### Backend
- **Schema**: `slackConnections` table added to `apps/api/src/db/schema.ts` with fields: id, teamId, slackTeamId, slackBotToken, triggerEmoji, monitoredChannels, createdAt
- **Migration**: `apps/api/drizzle/0011_slack_connections.sql`
- **Service**: `apps/api/src/services/slack.service.ts` — Slack signature verification (HMAC SHA256 with replay attack prevention), message processing, and response sending
- **Routes**: `apps/api/src/routes/slack.ts` — 6 endpoints:
  - `POST /api/slack/command` — /nyx slash command handler
  - `POST /api/slack/events` — Events API (url_verification, reaction_added, message)
  - `GET /api/slack/install` — returns Slack OAuth install URL
  - `GET /api/slack/callback` — OAuth callback, exchanges code for token, stores connection
  - `GET /api/slack/connection` — get connection status for a team
  - `PATCH /api/slack/connection` — update trigger emoji and monitored channels
  - `DELETE /api/slack/connection` — disconnect Slack
- **Config**: SLACK_CLIENT_ID, SLACK_CLIENT_SECRET, SLACK_SIGNING_SECRET added to env schema
- **Route registration**: Added to `apps/api/src/app.ts`

### Frontend
- **Component**: `apps/web/src/components/SlackIntegration.tsx` — settings card showing connection status, Connect/Disconnect buttons, trigger emoji editor, monitored channels management
- **API client**: `getSlackInstallUrl`, `getSlackConnection`, `updateSlackConnection`, `disconnectSlack` added to `apps/web/src/lib/api.ts`
- **Settings integration**: SlackIntegration component added to IntegrationsPanel in Settings page

### Tests (22 tests, all passing)
- `apps/api/src/__tests__/services/slack.service.test.ts` — 7 tests covering signature verification (valid, invalid, replay attack, wrong secret) and message processing
- `apps/api/src/__tests__/routes/slack.test.ts` — 15 tests covering all route endpoints

## Environment variables needed
- `SLACK_CLIENT_ID` — from Slack app settings
- `SLACK_CLIENT_SECRET` — from Slack app settings
- `SLACK_SIGNING_SECRET` — from Slack app settings

## Notes
- processSlackMessage is a placeholder that formats messages; the real Chaos Ingestion pipeline integration will wire in when that system is available
- Signature verification is enforced when SLACK_SIGNING_SECRET is set; skipped in dev if not configured
- Bot ignores its own messages (checks for bot_id) to prevent loops
- Channel monitoring only processes messages from explicitly configured channel IDs
