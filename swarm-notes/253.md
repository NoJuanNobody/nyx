# Ticket #253: Add auth middleware to ~96 unprotected API endpoints

## Implementation

Added a global `onRequest` hook in `apps/api/src/app.ts` that acts as a safety net after the existing `authMiddleware` plugin. The hook enforces that `request.user` is populated for all non-public routes. If a request reaches a protected endpoint without a valid user, the hook returns a 401 response.

### Public route allowlist

The following prefixes are exempt from the enforcement hook (they use alternative auth mechanisms or are intentionally public):

- `/health` -- health check endpoints
- `/api/webhooks/` -- GitHub/external webhook receivers (verified by signature)
- `/api/waitlist` -- public waitlist signup
- `/api/slack/callback` -- Slack OAuth callback
- `/api/slack/command` -- Slack slash commands (verified by Slack signature)
- `/api/slack/events` -- Slack Events API (verified by Slack signature)
- `/api/integrations/github/callback` -- GitHub OAuth callback
- `/api/integrations/gitlab/callback` -- GitLab OAuth callback
- `/api/integrations/bitbucket/callback` -- Bitbucket OAuth callback
- `/api/integrations/atlassian/callback` -- Atlassian OAuth callback

### How it works

1. The existing `authMiddleware` plugin (registered first) runs as a `preHandler` hook and attempts to populate `request.user` from a Bearer token (Clerk JWT or API key).
2. The new `onRequest` hook checks if the route matches a public prefix. If not, it verifies `request.user` is truthy. If no user is present, it returns `401 { error: 'Authentication required' }`.
3. This approach avoids modifying all 61 route files individually.
