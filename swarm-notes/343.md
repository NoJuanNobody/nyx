# Swarm note — #343: Ground AI Advisor "Fix these" in the connected codebase

## What was implemented

Grounded the "Fix these" CTA (and "Add missing sections" CTA) on the AI Advisor
in the team's indexed codebase via the existing `code_chunks` embedding pipeline
(PR #331), per the pinned scope-adjustment comment on the issue. When the team
has code chunks indexed, the top N similar chunks are retrieved via pgvector
cosine similarity and passed to the editor model as ground truth; when there
are none, a strict conservative prompt refuses to fabricate implementation
details and marks unverifiable sections with `> TODO: needs codebase context`.

### Files touched

- `packages/shared/src/schemas/ai.ts` — extended `editDocumentBody` with
  optional `documentId` + `teamId` (both or neither, enforced via refine).
- `apps/api/src/services/code-embedding.service.ts` — new
  `fetchRelevantCodeForDocument(documentId, teamId)` helper. Loads the doc,
  embeds `title + content[:2000]`, calls the existing `searchCode` for top-8,
  de-dupes sources. Soft 6s timeout, non-fatal on all failures.
- `apps/api/src/services/ai.service.ts` — `editDocument` gains optional
  `codeContents?: Array<{path, content}>`. Grounded/ungrounded system prompts
  are verbatim from the acceptance criteria. Grounded prompt embeds each file
  into the user message under its path header.
- `apps/api/src/routes/ai.ts` — `POST /ai/edit-document` calls the helper when
  both docId+teamId present, always returns 200 with
  `{content, grounded, groundingSources?}`. Retrieval failures caught and
  logged via `request.log.warn`, then fall through to ungrounded mode. The
  400 for "only one of docId/teamId" comes from the zod refine in the schema.
- `apps/web/src/lib/api.ts` — `editDocumentAI` accepts optional `options`
  (5th arg so the existing 4-arg signal call site stays minimally-touched),
  forwards docId+teamId, returns `{content, grounded, groundingSources?}`.
- `apps/web/src/components/AIAdvisor.tsx` — added `teamId?: string` prop,
  both `editDocumentAI` call sites (Fix these, Add missing sections) now pass
  `{documentId, teamId}`. Success messages reflect grounded-vs-ungrounded
  state. Dep arrays on both `useEffect`s extended to include docId + teamId.
- `apps/web/src/pages/DocumentEditor.tsx` — passes `teamId={doc.teamId}` to
  `<AIAdvisor />`.
- `apps/web/src/components/UnifiedAIPanel.tsx` — only the single
  `editDocumentAI` call at ~line 216 was modified (docId/teamId already
  existed on the props). Deliberately did NOT touch any state declarations
  to stay out of #345's way.
- `apps/web/src/components/AIEditPanel.tsx` — **unchanged**. Props don't
  carry docId/teamId, so per the instructions it uses the
  ungrounded-but-conservative prompt automatically.

## Scope adjustments honored

- Used existing `code-embedding.service.ts` (from PR #331), NOT the
  `codebase-scanner.service.ts` pipeline from the original issue body.
- Did not touch `codebaseScanner.service.ts` at all.
- Minimal diff on `UnifiedAIPanel.tsx` — only the single `editDocumentAI`
  call was modified, no state-decl churn (respects #345's parallel work).

## Backward compatibility

- `editDocument` service: new param is optional and trailing, all existing
  callers work unchanged.
- `editDocumentAI` client: new `options` param is optional and 5th, existing
  4-arg callers (including `AIEditPanel`) compile unchanged.
- `editDocumentBody` schema: new fields are optional; the both-or-neither
  refine only triggers if exactly one is present.
- Response body: new `grounded`/`groundingSources` are additive; legacy
  clients that only read `content` keep working.

## Not done / deferred (intentional, per issue out-of-scope)

- Semantic chunking of large code files (already in pipeline via PR #331).
- Streaming edits, cross-doc context, multi-repo teams.
- E2E Playwright coverage for the grounded vs ungrounded success-message
  branch — the unit + integration layer gives us the provable behavior and
  the UI text change is trivial/deterministic.
