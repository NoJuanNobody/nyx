# Ticket #193 — Add file upload support for raw data input

## What was done

- Installed `@fastify/multipart` in the api package
- Created `apps/api/src/services/file-parser.service.ts` with `parseFile(buffer, mimeType, filename)`:
  - `.txt`, `.md` — direct text import
  - `.csv` — parsed into a markdown table (handles quoted fields, escaped quotes)
  - Other formats — raw text with an unsupported-format note
  - MIME type refinement from filename when MIME is `application/octet-stream`
- Created `apps/api/src/routes/upload.ts` with `POST /api/documents/:id/upload`:
  - Accepts multipart form data (10 MB limit)
  - Parses the file and appends content to the existing document
  - Returns the updated document and any parser notes
  - Protected by `requireRole({ minimumRole: 'editor', source: 'document' })`
- Registered `@fastify/multipart` scoped to the upload route plugin (not globally, to avoid conflicts with existing multipart registrations in `audio.ts` and `voice-transcription.ts`)
- Registered the upload route in `apps/api/src/app.ts`
- Added mock for `upload.js` in `apps/api/src/__tests__/app.test.ts`

## Tests added

- `apps/api/src/__tests__/services/file-parser.service.test.ts` — 16 tests covering:
  - Plain text / markdown parsing
  - CSV to markdown table conversion (simple, quoted fields, escaped quotes, empty, header-only)
  - MIME type refinement from filename
  - Unsupported format fallback
- `apps/api/src/__tests__/routes/upload.test.ts` — 4 tests covering:
  - Successful upload appends content
  - 404 when document doesn't exist
  - 400 when no file uploaded
  - Note included in response for unsupported formats

All 20 new tests pass. Full suite: 80 passed, 2 pre-existing failures (voice-webhooks, recall-adapter — unrelated).
