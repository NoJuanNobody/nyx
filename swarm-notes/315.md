# Ticket #315 — Approval gates for destructive/external actions

## What was done

1. **Schema** (`apps/api/src/db/schema.ts`): Added `approvalStatusEnum` and `approvals` table with columns: `id`, `action`, `resourceId`, `requestedById`, `reviewedById`, `teamId`, `status`, `metadata`, `reason`, `expiresAt`, `reviewedAt`, `createdAt`.

2. **Service** (`apps/api/src/services/approval.service.ts`): CRUD operations for approvals — `create`, `approve`, `reject`, `check` (lookup by action+resource+team), `listByTeam`, `getById`. Default expiry is 7 days.

3. **Middleware** (`apps/api/src/middleware/approval-gate.ts`): `requireApproval()` preHandler factory. When a route is guarded:
   - If no approval exists, creates a pending one and returns 202.
   - If pending, returns 202 with approval details.
   - If approved, lets the request through.
   - If rejected/expired, returns 403.

4. **Routes** (`apps/api/src/routes/approvals.ts`): Registered at `/api`:
   - `GET /api/teams/:teamId/approvals` — list (requires editor role)
   - `GET /api/approvals/:id` — get single approval
   - `POST /api/approvals/:id/approve` — approve
   - `POST /api/approvals/:id/reject` — reject

5. **App registration** (`apps/api/src/app.ts`): Imported and registered `approvalRoutes`.

## How to use

Add `requireApproval({ action: 'delete_document' })` to any route's `preHandler` array to gate it behind approval. The middleware auto-creates pending approvals and blocks until an admin approves via the approvals API.
