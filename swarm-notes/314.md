# Ticket #314 — WebSocket push notifications for real-time updates

## What was done

1. **Installed `@fastify/websocket`** and `@types/ws` as dependencies in `apps/api`.
2. **Created `apps/api/src/services/pubsub.service.ts`** — in-memory pub/sub keyed by userId. Any service can call `pubSub.publish(userId, { eventType, payload })` to push events to all of that user's open WebSocket connections.
3. **Created `apps/api/src/routes/ws.ts`** — WebSocket endpoint at `/api/ws` that:
   - Authenticates via `?token=<clerk-jwt>` query parameter (browsers can't set custom headers on WebSocket)
   - Supports dev-bypass mode for local development
   - Subscribes the connection to the pub/sub service
   - Sends heartbeat pings every 30 seconds
   - Responds to client `ping` messages with `pong`
4. **Wired into `app.ts`** — registered the `@fastify/websocket` plugin and the WS route; added `/api/ws` to `PUBLIC_PREFIXES` since it handles its own auth.
5. **Wired into `notification.service.ts`** — after creating or updating a notification, the service now publishes a `notification.created` or `notification.updated` event over WebSocket in real-time.

## Files changed

- `apps/api/package.json` — added `@fastify/websocket`, `@types/ws`
- `apps/api/src/services/pubsub.service.ts` (new)
- `apps/api/src/routes/ws.ts` (new)
- `apps/api/src/app.ts` — registered websocket plugin and route
- `apps/api/src/services/notification.service.ts` — added pub/sub publish calls
