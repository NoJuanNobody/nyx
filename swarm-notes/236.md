# #236 — Add GitLab and Bitbucket Integrations

## What was done

### GitProvider Interface (`apps/api/src/services/git-provider.interface.ts`)
- Created a common `GitProvider` interface abstracting: `listRepos`, `getFileTree`, `getFileContent`, `createIssue`, `listIssues`, `createWebhook`, `deleteWebhook`, `exchangeCodeForToken`, `getAuthenticatedUser`
- Normalized response types: `GitRepo`, `GitIssue`, `GitUser`, `GitWebhook`, etc.

### GitLab Service (`apps/api/src/services/gitlab.service.ts`)
- Full GitLab REST API v4 integration
- OAuth 2.0 token exchange with refresh token support
- **Self-hosted GitLab support** via `setBaseUrl()` — configurable through `GITLAB_BASE_URL` env var
- Project listing, issue creation (with labels as comma-separated string per GitLab API), file tree, file content
- Webhook registration with push + issue events
- `GitLabTokenExpiredError` for 401 handling

### Bitbucket Service (`apps/api/src/services/bitbucket.service.ts`)
- Full Bitbucket REST API 2.0 integration
- OAuth 2.0 with Basic auth for token exchange (Bitbucket's required pattern)
- Repo listing, issue creation (using Bitbucket's `content.raw` format), file tree, file content
- Webhook registration (note: Bitbucket webhooks don't support shared secrets like GitHub/GitLab)
- `BitbucketTokenExpiredError` for 401 handling

### OAuth Routes (`apps/api/src/routes/integrations.ts`)
- `GET /api/integrations/gitlab/connect` — initiate GitLab OAuth with CSRF state cookie
- `GET /api/integrations/gitlab/callback` — handle callback, upsert integration
- `GET /api/integrations/:id/gitlab/repos` — list repos for connected GitLab
- `GET /api/integrations/bitbucket/connect` — initiate Bitbucket OAuth
- `GET /api/integrations/bitbucket/callback` — handle callback, upsert integration
- `GET /api/integrations/:id/bitbucket/repos` — list repos for connected Bitbucket
- Updated `POST /:id/test` to support testing GitLab and Bitbucket connections

### Schema Change (`apps/api/src/db/schema.ts`)
- Added `'gitlab'` and `'bitbucket'` to `integrationTypeEnum`

### Frontend (`apps/web/src/pages/Settings.tsx`)
- Added GitLab and Bitbucket to the provider selector on the integrations settings tab
- `handleConnect` routes to the correct OAuth endpoint per provider
- Account display maps `gitlabUsername` and `bitbucketUsername` from config

### Config
- Added `GITLAB_CLIENT_ID`, `GITLAB_CLIENT_SECRET`, `GITLAB_BASE_URL` to config schema and `.env.example`
- Added `BITBUCKET_CLIENT_ID`, `BITBUCKET_CLIENT_SECRET` to config schema and `.env.example`

### Tests
- `gitlab.service.test.ts` — 8 tests covering listRepos, createIssue, createWebhook, token exchange, auth user, self-hosted URL, deleteWebhook
- `bitbucket.service.test.ts` — 9 tests covering listRepos, createIssue, createWebhook, token exchange (Basic auth verification), auth user, deleteWebhook, getFileContent
- `git-provider.test.ts` — interface compliance tests for both providers

## Environment variables needed

| Variable | Required | Description |
|---|---|---|
| `GITLAB_CLIENT_ID` | For GitLab | GitLab OAuth Application ID |
| `GITLAB_CLIENT_SECRET` | For GitLab | GitLab OAuth Application Secret |
| `GITLAB_BASE_URL` | Optional | Self-hosted GitLab URL (e.g., `https://gitlab.mycompany.com`) |
| `BITBUCKET_CLIENT_ID` | For Bitbucket | Bitbucket OAuth Consumer Key |
| `BITBUCKET_CLIENT_SECRET` | For Bitbucket | Bitbucket OAuth Consumer Secret |

## What was not done
- The existing GitHub service was NOT refactored to implement the `GitProvider` interface. It already works and has extensive functionality (GraphQL, Projects v2, repo creation) that goes beyond the interface. Refactoring it would be scope creep and could break existing code paths.
- No database migration generated — the enum change requires `drizzle-kit push` in staging/production.
