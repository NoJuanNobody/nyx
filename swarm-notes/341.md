## What changed

**packages/shared**
- Removed `jsxPreviewBody` and `jsxPreviewRefineBody` zod schemas from `src/schemas/ai.ts`.

**apps/api**
- Removed `POST /api/ai/jsx-preview` and `POST /api/ai/jsx-preview/refine` route handlers + schema imports in `src/routes/ai.ts`.
- Removed `generateJSXPreview` and `refineJSXPreview` methods from `src/services/ai.service.ts`.

## Assumptions

- **CSP `unsafe-eval`**: the issue called out `unpkg.com` and `@babel/standalone` allowlist entries explicitly, so I removed `https://unpkg.com/` and `https://cdn.tailwindcss.com/` from both the helmet CSP (`apps/api/src/app.ts`) and the meta CSP (`apps/web/index.html`). I left `'unsafe-eval'` in the meta CSP because the issue did not explicitly require its removal and stripping it is a behavior change that could break other things (e.g. dev sourcemaps, future inline eval needs). If the team wants stricter CSP hardening, that should be a separate ticket.
- **`/api/mockups/render-jsx`**: the issue note said "Whatever that calls on the server side, follow the chain and remove it completely — don't leave a dead endpoint." So I removed the `POST /api/mockups/render-jsx` handler and the underlying `renderJSXToScreenshot` service function. The other endpoints in `apps/api/src/routes/mockups.ts` (`/generate`, `/attach`, `/attach-image`) and the corresponding `generateMockupHTML` / `renderToScreenshot` / `generateAndAttach` service functions are part of a separate "AI HTML mockup generator" feature (used by `apps/web/src/components/MockupGenerator.tsx`-style flows), and were left intact.
- **`/api/mockups/attach-image`**: this endpoint is still registered but its only known caller (the `mockupJsx` branch in `CreateTicketModal`) is being removed by this ticket. I left the endpoint in place because it's a generic image-attachment route, not a JSX-preview-specific one, and removing it would be out of scope. See follow-up below.
- **`generateMockupHTML` / `renderToScreenshot` exports**: these are still exported from `apps/api/src/services/mockup.service.ts` because they're used internally by `generateAndAttach`. I trimmed the imports in `routes/mockups.ts` to only `generateAndAttach`, since `generateMockupHTML` and `renderToScreenshot` were only being imported there but never directly called.
- **e2e selectors block scope**: the `jsxPreview: { ... }` block in `e2e/fixtures/selectors.ts` was the only JSX-preview-related selector group. Removed entirely.
- **Drizzle migrations**: grepped `apps/api/drizzle/` for `jsx` — no matches. Nothing to do.
- **Vite config**: grepped `apps/web/vite.config*` for `unpkg` / `babel` — no matches. The CDN allowlists lived only in the meta CSP and the helmet middleware, both addressed above.

## Governance conflicts

NONE. The removal is pure scope reduction; it does not introduce any new dependency on a hardcoded AI provider, does not touch secrets or env files, deletes (rather than skips) tests for removed code paths, and stays strictly within the issue's "Known touchpoints" inventory plus the chain-following the issue explicitly authorized.

## Follow-up items

- **Orphan `/api/mockups/attach-image`**: with the JSX-preview submit branch in `CreateTicketModal` removed, nothing in the web client now calls `POST /api/mockups/attach-image`. The endpoint and its tests are still in place because the endpoint is generic (not JSX-preview-specific) and removing it is outside this ticket's scope. Consider opening a follow-up to either delete it or wire it up to a future image-attach UI.
- **CSP `unsafe-eval` hardening**: `apps/web/index.html`'s meta CSP still includes `'unsafe-eval'`, which was originally added (as best I can tell) for `@babel/standalone` runtime compilation in the JSX-preview iframe. With the iframe gone, `'unsafe-eval'` may now be removable for a security improvement. Defer to a hardening ticket because removing it could break other things and the issue did not require it.
- **Bundle size warning**: `pnpm build` emits "(!) Some chunks are larger than 500 kB after minification" on the `dist/assets/index-*.js` chunk (1.27 MB). This warning predates this ticket and is unrelated to JSX preview removal.
