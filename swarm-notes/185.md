# Ticket #185 — Deliverable Generation System

## What was done
- Added `deliverables` table to `apps/api/src/db/schema.ts` with columns: id, documentId (FK to documents), stage, type (pdf/markdown/report enum), fileName, fileUrl, generatedAt, metadata (jsonb, nullable)
- Created `apps/api/src/services/deliverable.service.ts` with three methods:
  - `generateDeliverable(documentId, stage, type)` — looks up document, delegates to export service for PDF/markdown, creates DB record
  - `listDeliverables(documentId)` — returns all deliverables for a document
  - `getDeliverable(id)` — returns single deliverable by ID
- Created `apps/api/src/routes/deliverables.ts` with routes:
  - `POST /api/documents/:id/deliverables` — generate a deliverable (validates stage + type required, type must be pdf/markdown/report)
  - `GET /api/documents/:id/deliverables` — list deliverables for a document
  - `GET /api/deliverables/:id` — get single deliverable
- Registered routes in `apps/api/src/app.ts`
- Added route tests (9 tests) in `apps/api/src/__tests__/routes/deliverables.test.ts`
- Added service unit tests (10 tests) in `apps/api/src/services/__tests__/deliverable.service.test.ts`

## Test results
- All 19 new tests pass
- Pre-existing voice test failures (6 tests in recall-adapter and call-integration) are unrelated — those files were already modified on main

## Notes
- File storage is stubbed with path references (`/deliverables/{docId}/{fileName}`). Production use will need object storage (S3/GCS) integration.
- Report type currently stores metadata only — AI-formatted report generation can be layered on top when the AI provider abstraction is ready.
- A DB migration (`drizzle-kit generate`) will be needed to apply the new `deliverables` table and `deliverable_type` enum to the database.
