# Ticket #251: Fix voice agent not speaking

## Changes Made

### 1. voice-agent.service.ts (line 99)
- **Before:** Called `callIntegrationService.sendChat()` which posted text to meeting chat
- **After:** Calls `callIntegrationService.speak()` which routes to Recall.ai's `sendOutputAudio()` for TTS
- **Error handling:** Replaced empty catch block with `console.error` logging the failure reason

### 2. recall-adapter.ts (bot creation config)
- Added `output_audio.tts.provider: 'default'` to bot creation payload so Recall.ai configures TTS on the bot
- Added `chat.on_bot_join` greeting so participants know the bot is active

### 3. Tests Added
- `voice-agent.service.test.ts` — 11 tests covering speak() usage, __SKIP__ handling, error logging, stopped sessions, short buffers
- `recall-adapter.test.ts` — 4 tests verifying TTS config, chat greeting, output_media, and webhook config in bot creation payload

## What Was Not Changed
- Name detection logic was left as-is. The system prompt already handles this with the `__SKIP__` pattern, and the implicit name detection is not overly aggressive given the prompt constraints. A separate ticket could add explicit name matching as a pre-filter optimization if needed.
