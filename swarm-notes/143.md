# Ticket #143 — Stakeholder Workflow Trigger via CLI

## Changes

1. **`packages/cli/src/commands/proposals.ts`** (new)
   - `nyx proposals list <doc-id> [--status <status>]` — GET /api/documents/:docId/change-proposals
   - `nyx proposals generate <doc-id>` — POST /api/documents/:docId/change-proposals/generate
   - `nyx proposals approve <proposal-id>` — PATCH /api/change-proposals/:id/approve
   - `nyx proposals reject <proposal-id>` — PATCH /api/change-proposals/:id/reject
   - `nyx proposals push <proposal-id>` — POST /api/change-proposals/:id/push
   - All commands support `--format json|table` (default: json).

2. **`packages/cli/src/client.ts`** — Added `patch()` method to NyxClient for PATCH requests.

3. **`packages/cli/src/index.ts`** — Imported and registered `registerProposalsCommand` in the sentinel blocks.

4. **`packages/cli/src/__tests__/proposals.test.ts`** (new) — Tests verifying command/subcommand registration, option presence, and format flag on all subcommands.

## Design Notes

- Followed existing patterns from `docs.ts` command structure.
- `approve` and `reject` use PATCH; `generate` and `push` use POST; `list` uses GET.
- Query string for `list --status` only appended when the option is provided.
