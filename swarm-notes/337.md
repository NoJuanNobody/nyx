# 337 — Add text labels to document editor toolbar buttons

## What changed

Replaced the icon-only row-2 action toolbar above the document editor with icon+label buttons. Seven buttons in scope, all updated:

1. **Seed next stage** — `DocumentEditor.tsx` around `:354` — dynamic label uses the same `editorStageMap[lifecycleGetNextStage(...)]?.label ?? 'Next'` expression as the `title` attribute so tooltip and label always match
2. **Trace** — `:369` — `<Link>` with label "Trace"
3. **Create Ticket** — `:382`
4. **Bulk Tickets** — `:396` — `data-testid="bulk-generate-tickets"` preserved
5. **Export** — `:411` — dropdown trigger, `data-testid="export-menu-button"` preserved, dropdown positioning unaffected because the wrapper div was not restructured
6. **Save Version** — `:512`
7. **Save as Template** — `apps/web/src/components/SaveAsTemplateButton.tsx` — updated in place

Each button's class was changed from `rounded-md p-1.5 ...` to `flex items-center gap-1.5 rounded-md px-2 py-1.5 text-xs font-medium ...` (preserving the hover/disabled color variants). Each inner `<svg>` gained `flex-shrink-0`. A new `<span className="hidden sm:inline">Label</span>` was appended after the svg in each button, so labels are visible at ≥ 640px and hidden at < 640px — the existing `overflow-x-auto` on the toolbar container keeps the row horizontally scrollable on phones.

## Files modified

- `apps/web/src/pages/DocumentEditor.tsx` — six button class updates + spans for Seed / Trace / Create Ticket / Bulk Tickets / Export / Save Version
- `apps/web/src/components/SaveAsTemplateButton.tsx` — one button class update + span for Save as Template

## Assumptions

- **SaveAsTemplateButton was NOT already compliant.** Verified by reading the pre-change file at `SaveAsTemplateButton.tsx:42-54`. The button rendered only the svg inside a `rounded-md p-1.5` container with a `title="Save as Template"` tooltip but no visible text. Same treatment as the other 6 buttons applied.
- **Dynamic Seed label** reuses the exact expression from the `title` attribute (`` `Seed ${editorStageMap[lifecycleGetNextStage(...)]?.label ?? 'Next'}` ``) so the visible label and the tooltip can never drift apart. When `seeding === true` the `title` attribute temporarily shows `Seeding...` but the visible span keeps the static seed text — acceptable per AC ("Seed <next stage label>" is the stable name).
- **Trace label uses the same pattern as buttons** despite being an `<a>` instead of a `<button>` — the styling is uniform.
- **`DocDrawerToggle` cluster is explicitly NOT modified** per AC. Icons on the right side of the toolbar stay as-is.
- **`data-testid` attributes are preserved** on both the buttons that had them (`bulk-generate-tickets`, `export-menu-button`) and on the export dropdown items (`export-pdf`, `export-txt`, `export-docx`, `export-jupyter`). Existing e2e tests that select by testid continue to work.
- **Export dropdown positioning is unchanged** because the `<div className="relative">` wrapper at `:408` is untouched — only the inner trigger button's padding/label changed. The absolute-positioned dropdown still anchors to the wrapper at the correct location.
- **`#344`'s stale-doc fix is not regressed** — `seededIdRef`, `latestIdRef`, `scheduleSave` capture logic, and `saveMutation.onSuccess` cache-key logic were all left untouched.

## Governance conflicts

NONE. The issue is scoped to visible UI labels only; no policy-affected surface is touched.
