# Tickets #265 and #268 — Auto-save scan results + Smart sampling

## What changed

### #265: Code scan not saving documents to file explorer

**Root cause:** The scan route generated documentation via AI but never persisted it to the `documents` table. The frontend displayed it in a modal with "Copy Markdown" and "Done" buttons — once closed, the docs were gone.

**Fix:** The scan route now auto-saves documents to the DB after generation:
- `teamId` is now required (not optional)
- `userId` is extracted from `request.user.id`
- Each module doc and the merged overview doc are inserted into the `documents` table
- Response returns `{ documents, moduleCount, fileCount }` instead of `{ files, suggestedDocs }`
- Frontend `ScanRepositoryModal` invalidates `['documents', teamId]` on success so the file explorer refreshes
- `ScanResultView` now shows a success summary with created document list instead of raw markdown

### #268: Upgrade repo scanning to smart sampling

**Problem:** The old scanner was limited to 20 files matching narrow patterns (`readme`, `package.json`, `.ts` under `src/`), fetched sequentially, processed in a single 4096-token AI call.

**Solution — 6-phase smart sampling pipeline:**

1. **Module detection** — Files grouped into 7 modules (API Routes, Services, Components, Data Layer, Middleware, Utilities, Configuration) by directory path patterns. Unmatched files go into "Other".

2. **Smart sampling** — Each file scored by importance (index files +10, types +8, entry points +7, READMEs +5, large files +3, test files -5). Top 8 per module, capped at 80 total.

3. **Parallel fetch** — Files fetched in batches of 10 concurrent GitHub API calls.

4. **Per-module AI docs** — `bootstrapModuleDocs()` generates focused 2048-token docs per module.

5. **Merge** — `mergeModuleDocs()` combines module docs into one structured 8192-token document.

6. **Auto-save** — Each module doc + overview saved under `/repos/{owner}/{repo}/`.

**Graceful degradation:** Repos with < 5 source files fall back to the old single-prompt approach.
