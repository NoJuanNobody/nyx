# Ticket #194 — Implement plan-based usage limits for document creation and other features

## What was done

- Created `apps/api/src/services/plan-limits.service.ts` with:
  - Plan definitions for `free` (5 docs, no AI, 1 pipeline), `pro` (unlimited docs, AI, unlimited pipelines), `team` (pro + voice), `enterprise` (same as team)
  - `getPlanLimits(plan)` — returns the limits definition for a plan name, defaults to free for unknown plans
  - `getUserPlan(userId)` — reads from `stripe_customers` table, defaults to `'free'`
  - `checkLimit(userId, action)` — queries current usage counts against plan limits for actions: `create_document`, `use_ai`, `use_voice`
  - `getUsageSummary(userId)` — returns current usage counts for all tracked resources
- Created `apps/api/src/routes/plan.ts` with:
  - `GET /api/plan/usage` — returns the user's plan and full usage summary
  - `GET /api/plan/check/:action` — checks whether a specific action is allowed
- Registered `planRoutes` in `apps/api/src/app.ts` under `/api/plan`
- Created `apps/api/src/services/__tests__/plan-limits.service.test.ts` with 22 tests covering:
  - All plan definitions (free, pro, team, enterprise, unknown)
  - `getUserPlan` with and without stripe customer records
  - `checkLimit` for all three actions across all plan tiers, including edge cases (at limit, over limit)
  - `getUsageSummary` for free, pro, and team plans

## What was not done

- No middleware was added to enforce limits on existing routes (e.g., document creation). The service provides the building blocks; enforcement on specific routes is a separate concern.

## Notes

- The 6 pre-existing test failures in voice/recall-adapter tests are unrelated to this change (URL mismatch: `us-east-1.recall.ai` vs `api.recall.ai`)
- The `stripe_customers.userId` is a `text` column (Clerk ID), while `documents.createdById` is a UUID referencing the `users` table. The `checkLimit` function accepts the user's UUID (from `request.user.id`), so callers using `stripe_customers` would need the Clerk ID stored there to match
