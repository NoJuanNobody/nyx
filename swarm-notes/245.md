# Ticket #245: Fix documents losing their assigned stage

## Root cause

The document update endpoint (`PUT /api/documents/:id`) used `!== undefined` checks
to determine whether to include fields in the SQL UPDATE. While this works for
standard JSON-parsed bodies (where missing keys produce `undefined`), it is fragile
against edge cases such as middleware transformations or serialization quirks that
could introduce explicit `undefined` values.

## Fix applied

Changed field-presence checks in the PUT handler from `body.field !== undefined` to
`'field' in body` for all fields (title, content, path, status, stage). The `in`
operator checks whether the key exists in the parsed body object, which is the
canonical way to detect whether a client included a field in a partial-update payload.

Also tightened the gatekeeper guard: the stage transition gatekeeper now requires both
`'stage' in body` (key is present) AND `body.stage !== undefined` (value is not
undefined) before evaluating gate rules, preventing edge cases where an undefined
stage value could reach the gatekeeper evaluation.

## Files changed

- `apps/api/src/routes/documents.ts` -- partial update field-presence checks
- `apps/api/src/__tests__/routes/documents.test.ts` -- added test verifying stage is
  not cleared by content-only updates
