# Ticket #262 — Fix unauthenticated fetch and unvalidated redirects in frontend

## Changes

### Fix 1: Unauthenticated fetch in CreateTicketModal
- **File:** `apps/web/src/components/CreateTicketModal.tsx`
- Replaced raw `fetch('/api/mockups/attach-image', ...)` with the centralized `request()` helper from `../lib/api`, which automatically adds the `Authorization` header and `Content-Type`.
- Exported `request()` from `apps/web/src/lib/api.ts` (was previously private).

### Fix 2: Unvalidated redirects in SlackIntegration and Settings
- **File:** `apps/web/src/components/SlackIntegration.tsx` — Added validation that `data.url` starts with `https://` and contains `slack.com` before `window.location.href` redirect. Logs a warning and blocks redirect otherwise.
- **File:** `apps/web/src/pages/Settings.tsx` — Added validation on both `checkoutMutation` and `portalMutation` that `data.url` starts with `https://` and contains `stripe.com` before redirecting. Logs a warning and blocks redirect otherwise.

### Fix 3: PostMessage origin check in JSXPreviewRenderer
- **File:** `apps/web/src/components/JSXPreviewRenderer.tsx` — Added `event.origin` validation to the `message` event handler. Allows `'null'` (which blob: iframes send) and `window.location.origin`; silently drops all other origins.

## Testing
- All unit tests pass (5 packages, 72 web tests, 96 CLI tests).
