# 290 — Approval workflow: contextual spec surfacing in the UI

## Changes

### API — `apps/api/src/routes/documents.ts`
- Added `GET /api/documents/:id/related` endpoint
- Calls `contextMatchingService.findRelatedSpecs()` with the document's content and teamId
- Returns `{ related: Array<{ id, title, score, snippet, relevance, relationship }>, signals }`
- Requires viewer+ permission (uses `requireRole` with `source: 'document'`)

### Frontend API — `apps/web/src/lib/api.ts`
- Added `RelatedSpec` and `RelatedSpecsResult` interfaces
- Added `fetchRelatedSpecs(documentId)` function

### DocDrawer — `apps/web/src/components/DocDrawer.tsx`
- Added `'related'` to `DrawerPanel` union type
- Added "Related" panel tab with link icon to the toolbar
- Fetches related specs when the panel opens (with loading state and caching)
- Auto-triggers fetch when document stage matches `review` or `approval` (case-insensitive)
- Renders existing `ContextMatches` component (previously dead code) with fetched data
- Shows empty state message when no related specs found

### DocumentEditor — `apps/web/src/pages/DocumentEditor.tsx`
- Passes `stage={docStage}` prop to `DocDrawer`

## Validation
- `tsc --noEmit` passes for `@nyx/web`
- API source compiles cleanly (test file errors are pre-existing)
