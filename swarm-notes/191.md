# Ticket #191: Make template options clickable in pipelines

## Changes

### Backend: `apps/api/src/routes/documents.ts`
- Added `POST /api/documents/from-template` endpoint
- Accepts `listingId`, `teamId`, and optional `path` in the request body
- Fetches the marketplace listing by ID (must be published)
- Creates a new document pre-filled with the listing's title, content, and stage
- Increments the listing's download count (fire-and-forget)
- Returns 400 for missing teamId/listingId, 404 for missing listing, 500 on DB failure

### Frontend: `apps/web/src/pages/Marketplace.tsx`
- Updated `ListingCard` to be interactive: cursor pointer, hover border highlight (blue-300), and a "Use Template" overlay that appears on hover using Tailwind `group` utilities
- Added `onUseTemplate` callback prop to `ListingCard`
- Added `UseTemplateModal` component with:
  - Team selection dropdown (fetches from `/api/teams`)
  - Folder path input
  - Confirm/Cancel buttons with loading and error states
- Wired up `ListingsTab` to manage `templateToUse` state and show the modal

### Frontend: `apps/web/src/lib/api.ts`
- Added `createDocumentFromTemplate()` API function

### Tests: `apps/api/src/__tests__/routes/documents.test.ts`
- Added 4 new tests for the from-template endpoint:
  - Success case (201)
  - Missing teamId (400)
  - Missing listingId (400)
  - Listing not found (404)
  - DB insertion failure (500)

## Notes
- The endpoint reuses existing `requireRole` middleware with `editor` minimum role
- Download count increment is fire-and-forget to avoid slowing down the response
- The `UseTemplateModal` auto-selects the first team when teams load
- Added `data-testid` attributes on modal elements for future E2E tests
