# Ticket #149: PersonaPlex Voice Agent — Call Integration Layer

## What was done
- Created shared Zod schemas in `packages/shared/src/types/voice.ts` (MeetingPlatformSchema, CallStateSchema, AudioStreamEventSchema, CallSessionSchema)
- Created service types in `apps/api/src/services/voice/call-integration.types.ts` (CallSessionInternal, JoinCallConfig, CallLifecycleEvent, CallPlatformAdapter interface, VALID_TRANSITIONS state machine map)
- Created core service in `apps/api/src/services/voice/call-integration.service.ts` with:
  - Call lifecycle state machine: idle -> connecting -> in_call -> disconnecting -> ended (+ error)
  - joinCall, leaveCall, getStatus, onLifecycleEvent, registerAdapter methods
  - StubAdapter for testing (emits periodic silence events)
  - In-memory Map-based session store
  - EventEmitter-based lifecycle event bus
- Created Fastify route plugin in `apps/api/src/routes/voice.ts` with:
  - POST /join — join a call
  - POST /leave — leave a call
  - GET /status/:sessionId — SSE stream of lifecycle events
- Modified `apps/api/src/app.ts` to register voiceRoutes at `/api/voice`
- Modified `packages/shared/src/index.ts` to export voice types
- Created 18 unit tests covering state machine transitions, join/leave lifecycle, event emission, error handling, adapter registration, reset, and stub adapter behavior

## Design decisions
- Used provider-agnostic `CallPlatformAdapter` interface — new platforms (Zoom SDK, Google Meet, Teams) plug in by implementing connect/disconnect/onAudio
- StubAdapter defaults to 'zoom' platform for MVP testing
- SSE pattern follows existing agent.ts route pattern
- Service exported as singleton object following transcription.service.ts pattern
- State machine validates transitions explicitly; invalid transitions throw descriptive errors

## What was NOT done
- Real WebRTC/Zoom SDK/Google Meet SDK adapters (requires platform SDK dependencies and API credentials)
- Auth token validation for meeting platforms (stubbed as optional authToken field)
- Persistent session storage (in-memory Map only for MVP)
- Latency measurement (<200ms target requires real platform integration to validate)

## Tests
All 439 tests pass across 65 test files, including 18 new call-integration tests.
