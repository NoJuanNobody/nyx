# Ticket #178 — Implement Recall.ai CallPlatformAdapter for Zoom/Meet/Teams

## Changes

1. **`apps/api/src/services/voice/recall-adapter.ts`** — New Recall.ai-backed `CallPlatformAdapter` implementation:
   - `createRecallAdapter(platform)` factory producing adapters for all three `MeetingPlatform` values
   - `connect()` creates a bot via `POST /api/v1/bot`, polls status until in-call, then polls transcript data on an interval
   - Transcript entries are forwarded as `AudioStreamEvent` (`audio_chunk`) with speaker ID and timestamp
   - `disconnect()` stops polling, emits an `end` event, and calls the `leave_call` endpoint (idempotent)
   - Exports: `recallZoomAdapter`, `recallGoogleMeetAdapter`, `recallTeamsAdapter`

2. **`apps/api/src/services/voice/__tests__/recall-adapter.test.ts`** — 17 unit tests covering:
   - Platform identity for all three adapters
   - Bot creation via POST with correct auth headers
   - Status polling until in-call
   - Terminal failure status handling
   - Transcript polling with incremental entry forwarding
   - Graceful handling of transcript poll errors and 404s
   - Disconnect idempotency and leave_call API call
   - Missing `RECALL_AI_API_KEY` error

## Notes

- Uses native `fetch` (Node 18+) — no new dependencies added
- API key read from `process.env.RECALL_AI_API_KEY` at call time (not import time) so missing key is caught on first use
- The adapter maps Recall.ai transcript data to `AudioStreamEvent` with `type: 'audio_chunk'` — the `data` field contains the transcript text rather than raw audio, since Recall.ai handles audio capture/transcription server-side
- Bot status polling has a 120s timeout and 2s interval; transcript polling runs on a 3s interval
- The `leave_call` endpoint is used instead of `DELETE /bot/{id}` since it's the correct way to remove a bot from an active meeting

## Environment Setup Required

- `RECALL_AI_API_KEY` must be set in the API server environment (Railway, local `.env`)
- Obtain from https://recall.ai dashboard after creating an account
