# Ticket #35 — Trace View (AI Agent Map)

## What was built

### Backend
- `apps/api/src/services/trace.service.ts` — `buildTrace(documentId)` fetches audit trail events, builds DAG from parentEventId chains, enriches with human-readable labels. `getTraceSummary(documentId)` returns a plain-English summary of the trace chain.
- `apps/api/src/routes/trace.ts` — `GET /api/documents/:documentId/trace` returns `{ nodes, edges, summary }`. Uses `requireRole` with viewer minimum, same pattern as audit routes.
- Route registered in `apps/api/src/app.ts`.

### Frontend
- `apps/web/src/components/TraceView.tsx` — Linear card chain view (top-to-bottom), color-coded by event type, with icons, actor names, timestamps, and an AI summary at the bottom. Empty state included.
- `apps/web/src/pages/TracePage.tsx` — Page component with document title, back-link, and TraceView.
- `apps/web/src/lib/api.ts` — Added `fetchDocumentTrace()` and `TraceNode`/`TraceEdge`/`TraceResult` types.
- `apps/web/src/App.tsx` — Added `/documents/:id/trace` route.
- `apps/web/src/pages/DocumentEditor.tsx` — Added "Trace" link button in the toolbar.

### UI naming
"Trace" is used as the label everywhere in the UI — not "AI Agent Map".

## Tests added
- `apps/api/src/__tests__/routes/trace.test.ts` — 3 tests: returns nodes/edges/summary, handles empty state, verifies edge chains
- `apps/api/src/__tests__/services/trace.service.test.ts` — 6 tests: empty state, node building, edge building, System fallback actor, summary formatting

## What was skipped
- E2E tests for the trace page were not added — would need seed data with parentEventId chains to be meaningful.

## All tests pass
316 API + web tests passed with no regressions (9 new tests added).
