# Ticket #248: Add persistent pipeline access so users don't re-pay on switch

## Summary
Users were charged credits every time they switched to a pipeline. Now pipeline access is tracked persistently so users only pay once per pipeline.

## Changes

### Database (`apps/api/src/db/schema.ts`)
- Added `user_pipeline_access` table with columns: `id`, `user_id`, `team_id`, `pipeline_id`, `activated_at`, `credits_paid`
- Unique index on `(user_id, pipeline_id)` to prevent duplicate access records

### Backend Service (`apps/api/src/services/pipeline-access.service.ts`) — NEW
- `hasPipelineAccess(userId, pipelineId)` — checks if user already owns a pipeline
- `activatePipeline(userId, pipelineId, label, creditCost, teamId?)` — activates a pipeline; returns immediately without charging if already owned; otherwise deducts credits and records access
- `listOwnedPipelines(userId)` — returns all pipelines a user has activated

### API Routes (`apps/api/src/routes/pipelines.ts`) — NEW
- `GET /api/pipelines/owned` — lists user's owned pipelines
- `POST /api/pipelines/activate` — activates a pipeline (first-time only charges credits)
- `GET /api/pipelines/check/:pipelineId` — checks if user owns a specific pipeline

### Frontend API (`apps/web/src/lib/api.ts`)
- Added `fetchOwnedPipelines()`, `activatePipeline()`, `checkPipelineAccess()` API functions
- Added `OwnedPipeline` type

### Frontend UI (`apps/web/src/pages/Marketplace.tsx`)
- `PipelinesTab` now fetches owned pipelines and passes `isOwned` to each card
- Shows owned count in the header
- `PipelineCard` shows "Owned" badge for purchased pipelines instead of credit cost
- "Switch Pipeline" button for owned pipelines (free, no credit deduction)
- "Use Pipeline" with credit cost only shown for not-yet-owned pipelines
- Uses the new `/api/pipelines/activate` endpoint instead of direct `/api/credits/deduct`

### Tests (`apps/api/src/services/__tests__/pipeline-access.service.test.ts`) — NEW
- 7 unit tests covering `hasPipelineAccess`, `activatePipeline`, `listOwnedPipelines`
- All 991 tests passing

## Activation Flow
1. User clicks "Use Pipeline" on a pipeline card
2. Frontend calls `POST /api/pipelines/activate` with `pipelineId`, `pipelineLabel`, `creditCost`
3. Backend checks `user_pipeline_access` for existing record
4. If owned: returns `{ alreadyOwned: true }` — no credits charged
5. If not owned: deducts credits via `credits.service`, inserts access record, returns balance
6. Frontend updates UI, invalidates `owned-pipelines` and `credit-balance` queries
