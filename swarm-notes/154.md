# Ticket #154: Observability and Decision Throughput Monitoring

## What was done

### Backend (apps/api)
- **`src/services/observability/types.ts`** — All type definitions: MetricType, PipelineStage, Metric, HistogramBucket, AlertRule, AlertEvent, DashboardData, PipelineHealthSummary
- **`src/services/observability/metrics.service.ts`** — In-memory metrics store with counter, histogram, gauge support. Auto-prunes data older than 1 hour. Pre-defines pipeline metric names. Aggregates pipeline health per stage.
- **`src/services/observability/instrumentation.ts`** — Generic `withMetrics()` wrapper for async functions, plus manual `trackLatency()` and `trackError()` helpers. Designed to wrap service operations.
- **`src/services/observability/alerts.ts`** — Alert engine with 4 default rules: high transcription latency (>5s), low quality score (<4), high error rate (>10 avg in 5min), review bottleneck (>1hr wait).
- **`src/routes/observability.ts`** — FastifyPluginAsync with GET /metrics, /dashboard, /alerts, /pipeline-health endpoints.
- **`src/app.ts`** — Registered observability routes at `/api/observability`.

### Frontend (apps/web)
- **`src/components/MetricsDashboard.tsx`** — Dashboard component with stage cards (latency, error rate, throughput, status indicator), inline SVG bar charts, and alert list with severity badges.
- **`src/pages/ObservabilityPage.tsx`** — Page component with 30-second auto-refresh, loading/error states.
- **`src/App.tsx`** — Added `/observability` route inside Layout.
- **`src/components/Sidebar.tsx`** — Added Observability nav item after Repos.
- **`src/lib/api.ts`** — Added fetchObservabilityDashboard, fetchObservabilityMetrics, fetchObservabilityAlerts, fetchPipelineHealth API functions.

### Tests
- **`src/services/observability/__tests__/metrics.service.test.ts`** — 26 tests covering:
  - Counter increment, histogram recording, gauge set/get
  - Time windowing (old metrics pruned)
  - Pipeline health aggregation (latency avg, error rate, throughput)
  - Alert evaluation for all 4 default rules + custom rules
  - Instrumentation wrappers (withMetrics success/error, trackLatency, trackError)

## Notes
- The metrics store is in-memory only — no persistence. This is intentional for the MVP; a production system would back this with a time-series database.
- The `withMetrics()` wrapper is not yet integrated into existing services (transcription, parsing, etc.). Other services should import and wrap their core operations with it.
- The ObservabilityPage uses plain useState + useEffect for data fetching. React Query integration can be added when the dependency is available.
