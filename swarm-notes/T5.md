# T5 — Email Notification Delivery

## What was implemented

### `apps/api/src/services/notification-email.service.ts`

**NotificationEmailService** class with two main methods:

- **`queueOrSend(notification, userEmail, preference)`** — Routes notification emails based on user preference:
  - `emailMode: 'off'` or `emailEnabled: false` → skips entirely (no DB write, no email)
  - `emailMode: 'instant'` → sends immediately via `sendEmail`, logs to `emailDeliveryLog` with status `sent` or `failed`
  - `emailMode: 'daily'` or `'weekly'` → inserts into `emailDeliveryLog` with status `queued`

- **`sendDigest(userId, userEmail)`** — Processes queued notifications:
  - Fetches all `queued` entries from `emailDeliveryLog` joined with `notifications`
  - Groups by `eventType`, renders digest HTML via `buildDigestEmail`
  - Sends via `sendEmail`, updates all entries to `sent` (or `failed`)

**HTML builders** (exported, no external dependencies):
- `buildNotificationEmail(title, body, ctaUrl?, ctaText?)` — single notification email with dark Nyx branding
- `buildDigestEmail(items)` — grouped digest email with event type sections and counts

Singleton exported as `notificationEmailService`.

### `apps/api/src/__tests__/services/notification-email.service.test.ts`

9 tests covering:
- Instant mode calls `sendEmail` immediately
- Daily/weekly mode inserts queued entry (no email sent)
- Off mode and `emailEnabled: false` skip entirely
- Failed send still logs to delivery log
- HTML builder output correctness

## Dependencies used

- Existing `sendEmail` from `../services/email.js`
- Existing `db` from `../db/index.js`
- Schema tables: `emailDeliveryLog`, `notifications`
- `drizzle-orm` operators: `eq`, `and`

## Integration notes

- A cron job or scheduled task should call `notificationEmailService.sendDigest(userId, email)` for users with `daily` or `weekly` digest preferences.
- The `queueOrSend` method is designed to be called from the notification creation flow (e.g., after inserting into `notifications` table).
