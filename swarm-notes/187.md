# Ticket #187 — Social Media Publishing Integration

## What was done
- Created `apps/api/src/services/social-publish.service.ts` with:
  - `publishToTwitter` — validates 280-char limit, returns mock post URL
  - `publishToLinkedIn` — validates 3000-char limit, returns mock post URL
  - `publish` — dispatcher routing to the correct platform handler
  - `savePost` — persists social post records to DB
  - `getPublishHistory` — returns publish history for a document (newest first)
- Added `social_posts` table to `apps/api/src/db/schema.ts` with columns: id, documentId, platform, content, postUrl, status, publishedAt, createdAt
- Created `apps/api/src/routes/social.ts` with:
  - `POST /api/documents/:id/publish` — publishes content to a platform
  - `GET /api/documents/:id/social-posts` — lists publish history
- Registered routes in `apps/api/src/app.ts`
- Added 16 unit tests covering all service methods, validation edge cases, and error paths

## What was skipped
- Real API integration with Twitter/X and LinkedIn (stubs only, as specified)
- OAuth token management for social platforms — the route currently uses a hardcoded stub token
- E2E tests — this is a backend-only API feature with no frontend UI yet

## Notes
- Pre-existing test failures in `voice/__tests__/recall-adapter.test.ts` and `voice/__tests__/call-integration.service.test.ts` (6 tests) are unrelated to this ticket
- A database migration will need to be generated for the new `social_posts` table before deploying
