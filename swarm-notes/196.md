# Ticket #196 — Web search via agent functionality

## What was done
- Created `apps/api/src/services/search.service.ts` with `webSearch(query)` function
  - Calls Tavily API when `TAVILY_API_KEY` is set
  - Falls back to a stub response when the key is not configured
  - Returns `SearchResult[]` with `{ title, snippet, url }`
- Created `apps/api/src/routes/search.ts` with `POST /api/search` route
  - Accepts `{ query }` body, validates input, returns `{ results }`
- Added `TAVILY_API_KEY` as optional field in `apps/api/src/lib/config.ts`
- Registered `searchRoutes` in `apps/api/src/app.ts` at prefix `/api/search`
- Added unit tests in `apps/api/src/services/__tests__/search.service.test.ts` (4 tests, all passing)
  - Stub fallback when no API key
  - Successful Tavily API call with mapped results
  - Error handling for non-OK responses
  - Empty results handling

## Environment setup required
To enable live web search, set `TAVILY_API_KEY` in the environment (Railway, .env, etc.). Without it, the service returns a stub result indicating configuration is needed.

## Pre-existing test failures
The `call-integration.service.test.ts` tests in the voice service were already failing before this change (visible in the dirty working tree on main). Not related to this ticket.
