# swarm-notes/345.md — Closing AI chat drawer wipes conversation history

## Summary
The AI chat panel (`UnifiedAIPanel`) inside `DocDrawer` kept the entire
chat session in local `useState` hooks. Closing the drawer, switching
to another drawer panel, or navigating to another document unmounted
the component and silently destroyed all messages, the in-flight prompt
draft, the streaming buffer, status, and token-usage counters.

## Fix
Lift the chat session into a new zustand store keyed by `documentId`,
and consume it from `UnifiedAIPanel` instead of `useState`. State now
survives unmounts because it lives in the store, not in component
memory.

### New store: `apps/web/src/stores/aiChat.store.ts`
- Follows the same pattern as `ui.store.ts` / `auth.store.ts` (plain
  `create<T>()`, no middleware).
- Internal shape: `sessions: Record<documentId, AIChatSession>`. Each
  session holds `messages`, `prompt`, `selectedWorkflow`,
  `streamingContent`, `status`, and `tokenUsage`.
- `ensureSession(id)` lazily materializes an empty session on first
  access — no eager allocation for documents that are never opened in
  AI chat mode.
- All mutators (`appendMessage`, `updateMessage`, `setMessages`,
  `setPrompt`, `setSelectedWorkflow`, `setStreamingContent`,
  `setStatus`, `setTokenUsage`) are scoped to a single `documentId`
  and create the session on first write if needed.
- `reset(documentId)` clears **only** that document's session — other
  documents are untouched.
- `useAIChatSession(documentId)` is the React-facing hook. It returns
  the slice for the requested doc plus bound action helpers. The
  selector uses a frozen `EMPTY_SESSION_SENTINEL` for unmaterialized
  sessions so the snapshot is referentially stable across renders
  (avoids React 19's "getSnapshot should be cached" warning).
- Types `UnifiedMessage`, `UnifiedMessageBase`, `ToolCallEntry`,
  `SessionStatus`, `TokenUsage`, and `AIChatSession` are re-exported
  from the store so consumers import them from one place.
- **In-memory only.** No `zustand/persist`, no `localStorage`, no
  cross-tab sync. Page reload still clears — that's the documented
  follow-up.

### `apps/web/src/components/UnifiedAIPanel.tsx`
- Removed all six `useState` hooks (`prompt`, `selectedWorkflow`,
  `messages`, `streamingContent`, `status`, `tokenUsage`).
- Now reads its session via `useAIChatSession(documentId ?? NEW_DOC_SESSION_KEY)`.
  The sentinel key keeps the new-document case working without
  collapsing it into other docs' sessions.
- The local refs (`abortRef`, `streamingContentRef`, `chatEndRef`,
  `textareaRef`, `msgIdRef`) stay local — they're DOM / control-flow
  handles, not persistent state.
- `appendMessage` still bumps `msgIdRef` for monotonic IDs, but
  delegates the actual write to `storeAppendMessage(docId, msg, id)`.
- A new effect rebases `msgIdRef.current` from the max ID of the
  persisted messages on `sessionKey` change, so newly-appended
  messages after a remount don't collide with the IDs already in the
  store.
- A new unmount-cleanup effect aborts any active stream
  (`abortRef.current?.()`), clears the streaming ref, and resets the
  session's `status` from `'running'` back to `'idle'` if it was mid-
  stream when the panel unmounted. The stale-status check uses
  `statusRef` so the cleanup callback sees the latest status, not the
  status at first render.
- `clearHistory` (the existing visible "Clear chat" trash-can button)
  now calls the store's `reset()` for this `documentId` — users still
  have an explicit, opt-in way to blow away history.
- All `setMessages(prev => ...)` updaters that touched local state
  (toggle tool-call collapsed, accept/reject proposed edit, etc.) are
  rewired to `storeSetMessages(updater)`.
- **Untouched on purpose:** the `editDocumentAI(content, trimmed,
  history, controller.signal)` call site. Issue #343 is threading
  `{documentId, teamId}` into that exact line in parallel inside its
  own worktree, and the merge instructions are explicit that this
  agent must not race against that.

### `apps/web/src/components/DocDrawer.tsx`
Untouched. The conditional `{activePanel === 'ai' && aiChat && (<UnifiedAIPanel ... />)}`
mount stays — it doesn't matter that the panel unmounts on toggle
because the session lives in the store.

## Tests added

### `apps/web/src/__tests__/stores/aiChat.store.test.ts`
Five Vitest unit tests:
1. `ensureSession` lazily creates an empty session and the same
   reference is returned on repeated reads (no thrash).
2. `appendMessage` to session A does not bleed into session B.
3. `reset('doc-A')` clears only doc A; doc B is untouched.
4. The per-field setters (`setPrompt`, `setSelectedWorkflow`,
   `setStatus`, `setTokenUsage`) update only the targeted session.
5. `updateMessage` applies a transform over the messages array.

### `apps/web/src/__tests__/components/UnifiedAIPanel.test.tsx`
Three React Testing Library tests:
1. **Persistence across remount on same doc** — seed two messages in
   the store, mount the panel on doc A and assert both render, unmount
   the panel, remount on doc A, assert both messages are still
   visible.
2. **Cross-document isolation** — seed a message on doc A, mount on A
   (visible), unmount, mount on doc B (B is empty, A's message is
   not in the DOM), unmount, mount on A again (A's message is back).
3. **Unmount during running status** — seed a message and force the
   session into `'running'`, mount the panel, unmount it, assert the
   store's `status` for that doc was reset to `'idle'` while
   `messages` was preserved. Verifies the cleanup effect.

The test file installs a `Element.prototype.scrollIntoView` mock in
`beforeEach` because jsdom doesn't implement it and the panel calls
it in a scroll-on-message effect.
