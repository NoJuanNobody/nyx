# Issue #249 — Fix Slack integration not connecting

## Root cause
Slack admin routes (GET/PATCH/DELETE /connection, GET /install) had zero authentication middleware, meaning anyone could query, modify, or disconnect any team's Slack connection. Additionally, `processSlackMessage()` was a placeholder that did nothing useful, and the bot token was stored in plain text.

## Changes made

### P0: Auth middleware on Slack admin routes (`apps/api/src/routes/slack.ts`)
- Added `requireRole({ minimumRole: 'admin', source: 'request' })` to `/install`, `PATCH /connection`, `DELETE /connection`
- Added `requireRole({ minimumRole: 'viewer', source: 'request' })` to `GET /connection`
- `/callback`, `/command`, `/events` left as-is (use Slack signature verification or are OAuth redirects)

### P0: Real `processSlackMessage()` (`apps/api/src/services/slack.service.ts`)
- Replaced the placeholder with structured logging and a meaningful summary
- Handles empty messages gracefully
- Logs inbound messages with teamId, userId, channelId, and a text preview for observability
- Returns structured result with summary and source

### P1: Encrypt bot token (`apps/api/src/routes/slack.ts`)
- Imported `encrypt`/`decrypt` from `../lib/encryption.js`
- Bot token is now encrypted via AES-256-GCM before storing in the callback handler
- Added `sendSlackChannelMessage()` in slack.service.ts that decrypts the token before calling Slack API

### P1: Wire notifications to Slack (`apps/api/src/services/notification.service.ts`)
- After creating an in-app notification, fire-and-forget delivery to Slack
- Checks if the team has a Slack connection with monitored channels
- Sends formatted notification to the first monitored channel

## Test updates
- Added `requireRole` mock and `encryption` mock to `slack.test.ts`
- Added `request.user` decoration in test app builder so auth middleware passes
- All 1047 tests pass (109 test files)
