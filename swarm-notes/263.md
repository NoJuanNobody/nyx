# Ticket #263: Harden dev auth bypass and sanitize API error messages

## Changes

### 1. Production safety check for DEV_AUTH_BYPASS (`apps/api/src/middleware/auth.ts`)
- Added a module-level guard that throws `FATAL: DEV_AUTH_BYPASS must not be set in production` if `NODE_ENV === 'production'` and `DEV_AUTH_BYPASS === 'true'`.
- This runs on import, so the server will crash immediately on startup if misconfigured — preventing any requests from being served without auth.

### 2. Sanitized API error messages (`apps/web/src/lib/api.ts`)
- Replaced raw `throw new Error(\`API ${status}: ${body}\`)` with a sanitized version in both `request()` and `uploadIntakeAudio()`.
- The new behavior: parse the response body as JSON, extract `error` field if present, and show that to the user. Full error details are logged to `console.error` only.
- This prevents backend stack traces or internal error details from leaking to end users.

### 3. Skipped items
- **CSRF protection**: Already implemented (Bearer token auth mitigates CSRF).
- **HSTS headers**: Handled by #261 (`@fastify/helmet`).
- **API key hashing upgrade**: Deferred per ticket instructions.

## Test updates
- Updated `apps/web/src/__tests__/lib/api.test.ts` to expect the parsed error message (`'Not found'`) instead of the raw `'API 404'` string, matching the new sanitized behavior.
