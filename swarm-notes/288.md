# Ticket #288 — CLI: nyx query command

## What was done

1. **Query service** (`apps/api/src/services/query.service.ts`)
   - `queryDocs(query, teamId): AsyncGenerator<string>` retrieves relevant chunks via `retrieveChunks`, builds a context window, and streams a Claude response as text deltas.
   - Uses `claude-sonnet-4-20250514` with a documentation-focused system prompt.
   - Handles the zero-results case gracefully without calling Claude.

2. **API route** (`apps/api/src/routes/query.ts`)
   - `POST /api/query` — SSE endpoint accepting `{ query, teamId }`.
   - Streams text deltas as `data: {"text":"..."}` events, ends with `data: [DONE]`.
   - Follows the same SSE pattern used by `agent.ts`.
   - Registered in `app.ts` at prefix `/api/query`.

3. **CLI command** (`packages/cli/src/commands/query.ts`)
   - `nyx query "how does auth work?"` — streams the AI answer to stdout in real time.
   - `--format json` collects the full answer and outputs `{ "answer": "..." }`.
   - `--team-id` flag with fallback to `NYX_TEAM_ID` / config file.
   - Registered in `packages/cli/src/index.ts`.

## Build verification
- `pnpm --filter @nyx/cli build` passes cleanly.
- API build has pre-existing `@nyx/shared` module resolution errors unrelated to this change.
