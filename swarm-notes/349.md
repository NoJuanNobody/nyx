# 349 — Agent iteration ceiling + prompt caching

## Summary

Fixed two compounding bugs in `apps/api/src/services/agent/loop.ts`:

1. **Termination bug**: agent hit a hardcoded 10-iteration ceiling mid-task,
   overwrote any partial text with "Agent reached maximum iteration limit.",
   marked the session `completed`, and still charged credits.
2. **Token bloat bug**: no prompt caching, late/timid compression, tool_use
   blocks never compressed, `index_codebase` returned raw SDK output.

Branch: `swarm/349`, base: `main@a436516`.

## Bug 1 — termination fixes

- `MAX_ITERATIONS`: 10 → 25
- New constant `SOFT_ITERATION_WARNING = 20`; when reached, streams
  `[Warning: approaching iteration ceiling — the agent may wrap up soon.]`
  as a text event (only once per session).
- Refactored terminal early-exit into a shared helper `terminateIncomplete`
  called from both the max-iterations branch AND the token-budget branch.
  Previously the token-budget `break` fell through to the max-iterations
  block, reporting the wrong message.
- Preserves the **last non-empty `textOutput`** streamed from the model as
  `result`, with a trailing stop note:
  - Max iter: `\n\n[Stopped at iteration limit — output may be incomplete.]`
  - Token budget: `\n\n[Stopping early — approaching token limit. Please start a new message for further exploration.]`
- Session `status` set to `'failed'` (reused existing enum to avoid a
  Drizzle migration collision at slot 0015 — flagged in instructions).
- Credits are **only** deducted when the model actually produced usable text
  output. Runs that die mid-research with no text are free.
- `done` event payload includes `incomplete: true` so the UI can render a
  distinct state. `creditsUsed: 0` when no text was produced.
- Return value now includes `incomplete?: boolean`.

## Bug 2 — token usage reduction

- **Prompt caching.** `client.messages.create()` now sends:
  ```ts
  system: [{ type: 'text', text: systemPrompt, cache_control: { type: 'ephemeral' } }],
  tools: tools.map((t, i) =>
    i === tools.length - 1 ? { ...t, cache_control: { type: 'ephemeral' } } : t,
  ),
  ```
- **Removed `COMPRESS_AFTER_ITERATION`** (previously 3). Compression now runs
  every iteration after the first (`iteration >= 1`).
- **`compressOldToolResults` now walks assistant messages too.** Large
  `tool_use` block `input` payloads (>200 chars when serialized) are replaced
  with `{ _compressed: '[Compressed] {preview}... ({N} chars)' }`. Previously
  only `tool_result` blocks in user messages were compressed.
- **`keep` lowered from 2 to 1.** Only the most recent user turn is kept at
  full fidelity. Everything earlier is compressed.
- **`index_codebase` bounded at the tool side.** Executor now wraps
  `codeEmbeddingService.indexRepo()` with a summary containing:
  - `totalIndexableFiles`
  - `directoryCounts` (per top-level dir)
  - `sampleFilePaths` (up to 50)
  - A `note` when truncated telling the model to use `search_code`.
- **`cachedInputTokens` reporting.** `tokenUsage.cachedInputTokens` is
  accumulated from `response.usage.cache_read_input_tokens` and included in
  the `done` event payload.

## Tests

New file: `apps/api/src/services/agent/__tests__/loop.test.ts` (8 tests, all
passing).

Test scenarios covered:
1. 26 pure-tool_use iterations → ceiling hit, `deductCredits` NOT called,
   `incomplete: true`, result is only the stop note, `creditsUsed: 0`.
2. 25 iterations where the final one includes a text block → ceiling hit,
   partial text preserved with stop note appended, `deductCredits` IS called.
3. Iteration 20 emits the soft warning text event.
4. Token-budget early-exit is a distinct terminal block (not fallthrough);
   uses the token-stop note, not the max-iter stop note, with
   `incomplete: true`.
5. Normal completion (text response, no tool_use) deducts credits and
   reports `incomplete: undefined`.
6. `messages.create()` is called with `cache_control: ephemeral` on the
   system block and ONLY on the last tool.
7. `done.tokenUsage.cachedInputTokens` reflects `cache_read_input_tokens`.
8. Benchmark: cached run reports ≥50% fewer total tokens than an uncached
   baseline run (9× tool_use + 1× text, 10_000 tokens per call baseline vs
   1_000 uncached + 9_000 cache_read per call).

Pre-existing integration test `apps/api/src/__tests__/routes/agent.test.ts`
still passes with no changes — it mocks `runAgentLoop` wholesale.
