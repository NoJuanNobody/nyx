# Ticket #284 — Set up error monitoring (Sentry)

## Changes made

1. **Installed `@sentry/node`** in `apps/api`
2. **`apps/api/src/index.ts`** — Added Sentry initialization before app creation, gated by `SENTRY_DSN` env var
3. **`apps/api/src/app.ts`** — Added `Sentry.captureException(error)` in the global error handler before the 500 reply
4. **`apps/api/src/lib/config.ts`** — Added `SENTRY_DSN` as an optional URL env var in the Zod schema
5. **`.env.example`** — Added `SENTRY_DSN=` with a comment and link to Sentry docs
6. **`apps/api/src/services/ai.service.ts`** — Added `Sentry.captureException(err)` in the `resolveClient` catch block (line ~70) which silently swallowed BYOK key resolution errors

## Notes

- Only one catch block in `ai.service.ts` was truly swallowing errors silently (the BYOK client resolution). All other catch blocks are JSON parse fallbacks that return sensible defaults — those are expected behavior, not monitoring-worthy exceptions.
- TypeScript type check passes for all Sentry-related code. Pre-existing errors (`@nyx/shared` module resolution) are unrelated.

## Setup required

To activate Sentry, set `SENTRY_DSN` in the environment (Railway dashboard for staging/production). Get the DSN from: Sentry project settings > Client Keys (DSN).
