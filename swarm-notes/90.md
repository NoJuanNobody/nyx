# Ticket #90 — Historical Context Matching

## What was built

### Backend
- **`apps/api/src/services/context-matching.service.ts`** — `findRelatedSpecs(newInput, teamId)` fetches all team documents from the DB, sends them with the new input to Claude for semantic analysis, and returns validated matches + signals.
- **`apps/api/src/routes/context.ts`** — `POST /api/intake/context` accepts `{ rawInput, teamId }`, calls the service, returns `{ matches, signals }`.
- **`apps/api/src/app.ts`** — registered context route at prefix `/api/intake`.

### Frontend
- **`apps/web/src/components/ContextMatches.tsx`** — displays related spec matches (with relevance/relationship badges and doc links) and signal badges (Recurring Pattern = green, Contradiction = red, Scope Creep = yellow). Collapsible section.
- **`apps/web/src/pages/IntakePage.tsx`** — textarea for raw input, "Analyze Context" button, calls `findContextMatches()`, renders `ContextMatches` below.
- **`apps/web/src/lib/api.ts`** — added `findContextMatches()`, `ContextMatch`, `ContextSignal`, `ContextMatchResult` types.
- **`apps/web/src/App.tsx`** — registered `/intake` route.

### Tests
- **6 backend unit tests** (`context-matching.service.test.ts`): empty docs, successful AI analysis, invalid doc ID filtering, invalid JSON fallback, missing API key error, invalid signal type filtering.
- **7 frontend unit tests** (`ContextMatches.test.tsx`): empty render, loading state, match rendering with links/badges, signal badges, collapse/expand, header counts.

## Design decisions
- Reused the existing `aiService` pattern (Anthropic SDK, `requireClient()`, JSON parsing with fallback).
- Response validation filters out AI hallucinated doc IDs by checking against the actual team documents fetched from DB.
- No new DB schema changes — queries existing `documents` table.
- The IntakePage is a standalone page at `/intake` (no existing IntakePage existed to integrate into).
