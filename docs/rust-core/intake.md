# Intake / chaos ingestion (AI-73)

Rust module: `crates/nyx-core/src/intake/`. Tests: unit tests in each file plus `crates/nyx-core/tests/intake.rs`. Migration: `0173_intake_records.sql` (version 173).

Flow: `IntakePipeline::ingest_file | ingest_text` -> record `received -> parsed` -> `structuring_prompt` -> **caller runs the LLM** -> `apply_structuring_response` -> record `structured` or `clarification_needed` -> optionally create a document and `index_record` (chunks via `store::chunks`).

## Input kinds and sniffing

`InputKind`: text, markdown, csv, pdf, docx, image, audio, pcb, unknown. `kind::sniff` checks magic bytes first (PDF, PNG, JPEG, GIF, WebP, WAV, MP3/ID3, M4A, WebM), then whether a zip is a real `.docx` (`[Content_Types].xml` + `word/document.xml`), then PCB (extension or `(kicad_pcb` header), then declared MIME / extension, then a UTF-8 heuristic. Content wins over labels; a disagreement sets `mismatch` and the pipeline adds a note to the record. Unknown binary data and foreign zips are rejected.

## Safety

- Size caps: 10 MB for everything except audio, 25 MB for audio (TS values), empty input rejected.
- File names: `sanitize_filename` keeps the last component, drops control characters, rejects `.`/`..`/empty/over 255 bytes. `safe_join` rejects absolute paths, `..`, drive prefixes for callers that persist originals.
- DOCX: entry count, entry-name check (zip-slip), declared total size, per-entry compression ratio (default 200:1 above 1 MiB), and a hard cap on the bytes actually inflated (headers can lie). DOCTYPE in the XML is refused. Nothing is written to disk.
- PDF: `lopdf` with `extract_text_with_limit` (bounded decompression per page), page cap, encrypted files refused, run under `catch_unwind`.
- All parsers truncate extracted text to `Limits::max_extracted_chars`.

## Engines (out of scope, traits only)

`Transcriber` and `OcrEngine` have fakes (`FakeTranscriber`, `FakeOcr`). Intended real bindings: **whisper.cpp** through `whisper-rs` for audio (audio decoded to 16 kHz mono with `symphonia`, model file chosen by the user; alternative: OpenAI-compatible `/audio/transcriptions` endpoint) and **Tesseract** (`leptess`) for images, both behind optional cargo features so the default build stays light. Scanned PDFs (no text layer) are reported with a note; rendering pages to feed OCR is not implemented.

## LLM boundary

No LLM is called. `StructuringPrompt { system, user, max_tokens }` is built for raw input, input plus clarification answers, and transcripts; `parse_spec_response` / `parse_transcript_response` / `voice::parse_intelligence_response` turn the reply into typed values and never fail (unparseable output becomes a low-confidence spec asking for a retry, as in the TS). Plug these into `LlmProvider` once AI-75 lands.

## Parity gaps and decisions

- **Chunking quirk preserved.** The TS loop does not stop at the window that reaches the end, so it emits up to `overlap` short trailing chunks that are suffixes of the last chunk. `ChunkOptions::default()` keeps this (golden-tested); `drop_covered_tail: true` removes it. Recommend flipping the default before embeddings are generated at scale.
- Chunk offsets are UTF-16 units like JS; a cut inside a surrogate pair gives U+FFFD where JS keeps a lone surrogate.
- CSV: like the TS, lines are split before quote handling, so quoted fields containing newlines are not supported; `|` in cells is not escaped.
- PCB: dimensions only from `gr_line` on `Edge.Cuts` with non-negative coordinates; KiCad 8 `(property "Reference")` footprints are not in the BOM.
- `doc-transformer` date: `YYYY-MM-DD HH:MM:SS UTC` instead of locale-dependent `toLocaleString()`.
- LLM list fields: non-string items are dropped (TS kept whatever the model returned).
- Hosted features dropped: rate limiting (`@fastify/rate-limit`), role checks, team scoping beyond the `team_id` column.
- Migration version 173 follows the wave-3 `100+NN` convention. The existing test `extra_migrations_extend_core_and_foreign_keys_are_on` used version 100 for its throwaway migration, which now sorts below core; it was changed to `100_000`. Other wave-3 branches will hit the same test.
- New dependencies in `nyx-core`: `lopdf` (default features off), `zip` (deflate only), `quick-xml`, `regex`.
