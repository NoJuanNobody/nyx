# Nyx docker/local run issue summary

Symptoms
- Postgres container boots and reports "database system is ready".
- API container starts (`tsx watch src/index.ts`) and logs requests to `http://localhost:3001/` returning `401 Unauthorized`.

Root cause
- The global auth middleware at [`isDevBypass`](apps/api/src/middleware/auth.ts:44) only skips auth when `NODE_ENV=development` **and** `CLERK_SECRET_KEY` is **not** set.
- With any `CLERK_SECRET_KEY` value present in `.env` (loaded in [`config`](apps/api/src/lib/config.ts:8)), the middleware treats the server as Clerk-enabled and requires a valid `Authorization: Bearer <token>` header (or `sd_` API key hash match) for every route, including `/`. Without that header you get `401` from [`authMiddleware`](apps/api/src/middleware/auth.ts:179).

How to run locally with Docker
1) Ensure `.env` matches Docker Compose defaults:
   - `DATABASE_URL=postgresql://postgres:devpassword@db:5432/nyx_dev`
   - Keep `NODE_ENV=development`.
   - **Remove or comment out** `CLERK_SECRET_KEY` and `CLERK_PUBLISHABLE_KEY` to enable the dev bypass user.
2) Recreate containers so the updated `.env` is picked up: `docker-compose up --build`.
3) After startup, hit `http://localhost:3001/api/health` (or any `/api/*` route). In dev bypass mode responses should succeed without auth; without bypass you must send a valid Clerk JWT or an `sd_` API key.
4) If you see DB errors, run migrations inside the API container: `pnpm --filter @nyx/api db:migrate` (the dev image does not auto-run migrations).

If you intend to test real auth
- Keep `CLERK_SECRET_KEY`/`CLERK_PUBLISHABLE_KEY` set and send `Authorization: Bearer <clerk-jwt>` or an `sd_` API key that exists in `api_keys` (hashed) to avoid 401s.
